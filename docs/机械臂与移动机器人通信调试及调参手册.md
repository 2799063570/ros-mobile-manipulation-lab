# 机械臂与移动机器人通信调试及调参手册

适用范围：本仓库 ROS 1 系统中的 AUBO 机械臂、WheelTec 移动底盘、STM32 遥控、激光导航与跟随，以及移动操作联调。整理日期：2026-10-24。

本文区分“当前实现”“已有记录”“建议补充”。参数值是当前源码或配置中的值，不是所有车型、负载、固件都适用的推荐值。本次仅整理文档，未连接硬件、执行运动或重新运行历史测试。

## 1. 调试总顺序与系统边界

按以下顺序逐层确认，不要用增大超时、误差阈值或速度来掩盖前一层故障：

1. 电源、急停、机械安装、负载、网线与串口接线。
2. IP/端口、设备路径、串口权限、固件和协议版本。
3. 原始数据格式、校验、单位、方向、时间戳与新鲜度。
4. ROS 话题连接、坐标变换、控制器状态及指令源归属。
5. 指令生成、发送耗时、缓冲积压、反馈跟随及停止过程。
6. 里程计标定、定位导航、机械臂平滑与任务协调。

### 1.1 三条通信链路不能混用

| 链路 | 上位与下位的职责 | 当前接口 |
| --- | --- | --- |
| 机械臂控制 | ROS 生成或插补关节点，控制柜接收并执行 | TCP SDK，示例地址 `192.168.1.2:8899` |
| STM32 机械臂遥控 | MCU 采集摇杆/按键；PC 校验会话、调用点动与 home | 串口 `115200 8N1`，v2 POLL/INPUT/FEEDBACK |
| WheelTec 底盘 | ROS 发车体速度；底盘控制板负责电机闭环并回传数据 | 串口默认 `115200`，固定长度帧与 BCC |

机械臂真机点动入口默认走 `ros_control → JTC → AuboHW → SDK`；`backend:=sdk` 则由 `DirectSdkBackend` 直接发点。STM32 点动串口桥复用点动控制器，不建立另一套机械臂 SDK 写入通道。

导航的典型链路为 `move_base → /cmd_vel_raw → laser_safety_filter → /cmd_vel → 底盘串口`。只有启动并正确接入过滤器时，该链路的激光停车与运动锁才有效。键盘或其他节点直接发 `/cmd_vel` 会绕过它。

### 1.2 单一指令出口

- 机械臂点动、MoveIt 执行、视觉伺服和示教器运动应明确切换，避免并行写入。
- 本包真机写入路径共享 `/tmp/aubo_motion_writer.lock`；锁不能约束其他主机、示教器或仓库外客户端。不要删除锁文件绕过互斥。
- 底盘导航、键盘、遥控、跟随需要一个明确的仲裁出口。多个发布者同时发速度时，停车零值可能被另一来源的非零值覆盖。
- 使用 `rostopic info /cmd_vel`、`rostopic info /cmd_vel_raw` 和控制器命令话题核对实际发布者；多发布者场景应补充优先级、超时与独占授权机制。

## 2. 上下位通信约定

### 2.1 每条协议必须说清的内容

以下是新协议设计和联调验收约定；不能直接给现有固件加字段而不同时升级两端。

| 项目 | 必须约定的内容 | 防止的问题 |
| --- | --- | --- |
| 物理接口 | 电平、接线、共地、波特率、数据位、校验、停止位 | 接口损坏、乱码、偶发丢帧 |
| 帧格式 | 帧头、版本、类型、长度、字段偏移、最大长度 | 分包粘包、错位、越界 |
| 数值编码 | 字节序、有符号表示、缩放、范围、无效值 | 正负反转、数值放大、截断溢出 |
| 单位与坐标 | m/mm、rad/deg、车体或工具坐标、轴正方向 | 运动方向错误、速度数量级错误 |
| 时序 | 周期、允许延迟、超时、重试次数、有效期 | 长时间执行旧命令 |
| 会话与编号 | 重启标识、序号回绕、重复帧、乱序帧规则 | 重连重放、重复 HOME、迟到使能 |
| 应答语义 | 收到、接受、执行中、完成、取消完成、失败分别编码 | 把收到请求误认为已经到位 |
| 停止与恢复 | 谁触发停车、停车方式、停稳确认、是否需重新授权 | 断链后继续运行、恢复即自启动 |
| 状态有效性 | 采样时刻、反馈年龄、有效位、故障码 | 用缓存状态判断就绪 |
| 兼容性 | 固件/PC 版本、可选功能、未知字段处理 | 新旧协议静默误解码 |

建议连续速度命令使用“最新有效值覆盖旧值”，离散动作使用“请求编号去重”。重试相同请求应返回该请求的已有结果；用户再次要求执行才分配新编号。发送返回不明确时，不直接重发有位移或其他副作用的命令。

CRC/BCC 用于检出部分传输错误，不能证明数据新鲜、动作合理、已执行，也不提供身份认证。TCP 的有序可靠传输同样不代表调用满足实时预算。

### 2.2 当前 STM32 机械臂遥控约定

完整字段以 [笛卡尔串口协议](../aubo/aubo_remote_bridge/CARTESIAN_SERIAL_PROTOCOL.md) 和协议 C 文件为准。

| 内容 | 当前约定 |
| --- | --- |
| 电气与串口 | 3.3 V TTL，TX/RX 交叉、GND 共地；115200、8N1、无流控 |
| 帧 | `A5 5A`，版本 `02`；POLL=`0x11`、INPUT=`0x12`、FEEDBACK=`0x13` |
| 字节序与校验 | 多字节小端；CRC-16/CCITT-FALSE，CRC 低字节先发；标准测试串 `123456789` 得 `0x29B1` |
| 轮询 | PC 约每 20 ms 发 POLL，同时只等待一个 INPUT，响应窗口 100 ms |
| 防旧帧 | INPUT 回显当前 session/sequence；重复帧不刷新看门狗；超时后换 session |
| 离散操作 | ENABLE/STOP/HOME/CANCEL/RESET 使用 request_id 去重；新会话首帧仅建立基线 |
| 运动许可 | 输入有效、校准完成、显式使能且允许运动键按下，才发非零速度 |
| 使能完成 | 服务返回后仍需收到新的 `ENABLED_IDLE`；确认窗口最多 1 秒 |
| 断链与恢复 | 输入超时后发零、取消 home、请求禁用；恢复后重新回中并显式使能 |
| 单位 | speed 单位 0.1 mm/s，关节反馈 mrad，方向分量 -1000..1000 |

不要直接发送 C 结构体内存；按字段显式编码，避免填充、大小端和对齐差异。旧 HOME/ZERO 入口使用的 `0x01/0x02/0x03` 不能当作本点动入口报文。

### 2.3 当前 WheelTec 底盘串口约定

以下按 [wheeltec_robot.cpp](../turn_on_wheeltec_robot/src/wheeltec_robot.cpp) 的 PC 端实现整理。下位机实际执行、限速与失联行为还需核对固件。

发送帧共 11 字节，偏移从 0 开始：

| 偏移 | 内容 |
| --- | --- |
| 0 | 帧头 `0x7B` |
| 1～2 | 预留，当前发送 0 |
| 3～4 | `linear.x × 1000`，有符号 16 位，高字节在前 |
| 5～6 | `linear.y × 1000`，同上 |
| 7～8 | `angular.z × 1000`，同上 |
| 9 | 对字节 0～8 按位异或的 BCC |
| 10 | 帧尾 `0x7D` |

例如 `linear.x=0.10 m/s` 对应整数 100；`angular.z=0.20 rad/s` 对应整数 200。差速底盘应约定 `linear.y=0`，不要把全向底盘指令直接沿用。

接收帧共 24 字节：0 为帧头，1 为停止标志字段，2～7 为三方向速度，8～19 为加速度计和陀螺仪原始值，20～21 为电压缩放值，22 为字节 0～21 的异或校验，23 为帧尾。多字节值按高字节在前解析；IMU 缩放还依赖固件量程及头文件常量，须联合确认。

当前帧中没有 session、请求序号、命令有效期和逐命令完成应答，不能套用遥控协议的防重放能力。PC 发出速度后，要通过回传速度及现场运动验证执行。

### 2.4 超时与停车责任分配

| 层次 | 当前能力或需要补充的约定 |
| --- | --- |
| 操作端/任务端 | 松手发零；离散动作取消需等待结果，不把“已发送 cancel”显示为“已停止” |
| 机械臂点动 | 输入/反馈超时、跟随误差、限位、奇异与碰撞保护；具体故障能否继续生成减速点取决于后端状态 |
| SDK 流控 | 诊断失效、下发失败、积压或供点预算超限时停流；无法撤回已入柜或仍在途的点 |
| 底盘激光过滤器 | 速度/激光接收超时、运动锁或障碍触发时输出零速度，前提是没有绕过该出口 |
| 底盘 PC 驱动 | 速度接收超时尝试发零；串口故障尝试发零、断开重连，打开端口时先发零 |
| 下位机/控制柜 | 须实测通信完全断开、PC 掉电、进程被强制结束时的本地停止行为；PC 已断链时不能依赖它再发停车帧 |

软件停车存在输入检测、调度、网络、排队和制动延迟，硬件急停另行验证。底盘恢复串口后先发零不等于具备重新授权机制：如果上游持续发布旧的非零意图，后续回调仍可能重新驱动车辆。

## 3. 机械臂 SDK 与执行链调试

### 3.1 通信与启动问题

| 现象 | 排查顺序与处理 |
| --- | --- |
| IP 不通 | 控制柜电源、实际 IP、网段、网线、路由、网卡选择；检查地址冲突 |
| IP 通但端口不通 | 核对 8899 是否为当前服务端口、服务是否启动、网络策略是否阻断 |
| 端口通但登录失败 | 核对账号和返回码；直接 SDK 当前每条连接最多登录 5 次，失败间隔 500 ms |
| 写入锁失败 | 找出已有控制进程并正常退出，不删除锁文件 |
| 登录成功但不能运动 | 分别查 startup、握手、真实机器人检测、停止状态、急停与碰撞状态 |
| 收不到关节推送 | 查回调注册及数据链路；直接 SDK 2 秒内无首帧会拒绝进入透传 |
| 反馈超时 | 记录样本年龄、累计帧数、最大帧间隔；排查 SDK 回调、网络、CPU 调度 |
| TCP2CANBUS 失败 | 记录返回码和当前模式，确认其他客户端已退出、机械臂已停稳 |
| 控制器不就绪 | 默认后端检查 JTC 是否加载且 running、命令话题及 controller_manager 路径是否一致 |
| 上电后方向或 TCP 偏差大 | 核对关节顺序、零位、base/tool 链、实际工具安装和模型；先查模型再调控制增益 |

只读网络检查示例，不触发运动：

```bash
ip -br addr
ip route get 192.168.1.2
ping -c 10 192.168.1.2
nc -vz -w 2 192.168.1.2 8899
```

`nc` 仅在已安装时使用。ping 正常只说明 ICMP 链路表现，不能证明 SDK RPC 的耗时和连续供点能力。

### 3.2 如何核验关节点发送正确

按五层核验，不能只看 `ret=0`：

1. **格式与单位**：六轴顺序与 KDL 链、控制器一致；关节位置 rad；线速度 m/s；拒绝 NaN/Inf、缺关节和无效坐标系。
2. **轨迹约束**：固定 5 ms 点周期；上层限制速度、加速度、jerk，并检查限位和候选点的制动尾段。直接 SDK 边界再次检查有限值及速度、加速度连续性。
3. **调用结果**：记录批次、点数、返回码、开始/返回时刻、生成耗时和最大关节增量。
4. **接收与积压**：结合 MAC 诊断观察缓冲；发送前预留额度，在途点和诊断期间不确定点均保守计入积压。
5. **执行反馈**：检查原始关节反馈年龄及指令与反馈偏差；确认到位还需要实际反馈和速度满足条件。

`SdkFlowControl` 不按“经过了多少时间”自动释放额度，只接受有效诊断观测返回空间。该模型依赖代码中注明的协议假设：成功发送表示服务端接受，诊断在请求/响应区间内采样。它不构成 SDK 硬实时保证。

### 3.3 缓冲、阻塞与断流

直接 SDK 点动默认首次发 10 点，随后每 20 ms 补 4 点，每点 5 ms。状态使用推送、诊断独立线程查询，降低互相阻塞，但发送接口本身仍是同步调用。

```text
名义缓冲时长 = MAC 关节标量数 / 6 × 5 ms
60 标量 = 10 个六轴点 = 50 ms
360 标量 = 60 个六轴点 = 300 ms
```

50 ms 是名义前瞻，300 ms 是保守积压硬上限所对应的时长，都不是实际停止时间。停止还包括检测、在途调用和减速尾段等。

| 现象 | 应优先处理 |
| --- | --- |
| 下发调用耗时高 | 查调用耗时分布、网络与 SDK 等待位置；不能靠独立诊断线程解决发送接口自身阻塞 |
| 诊断查询耗时高 | 查请求延迟、其他客户端及 SDK 内部等待；保持诊断超时保护 |
| 点生成耗时高 | 确认构建模式，检查碰撞网格、场景复杂度与尾段采样成本 |
| 锁等待/调度间隙高 | 查 CPU 负载、共享锁范围、同步回调和后台任务 |
| 已建立轨迹流后 MAC 为零 | 视为断流处理；当前直接 SDK 拒绝断流后追赶恢复 |
| 返回成功但已停流 | 保留该批次日志和在途占用；成功不等于已执行完成，不立即补发或重试 |

已有记录：直接 SDK 下发曾耗时 65.26 ms、89.24 ms，超过 20 ms 补点节拍；诊断也曾出现约 104.51 ms、310 ms 耗时。只读通信改善、静止禁用启动成功和离线流控通过，都不能证明实际运动连续供点通过。当前直接 SDK 路径仍未完成连续运动验证。

默认 `ros_control` 入口使用 `mac_buffer_target=120`、`trajectory_preload_points=20`、`control_frequency=200`，与直接 SDK 参数不是同一组配置。其真机 XYZ 点动、home、平滑性与停止延迟仍需验证。

### 3.4 日志与反馈选择

- 默认后端保留 `[AuboHW]`、JTC、`[cartesian_jog]` 日志。
- 直接 SDK 保留 `[sdk/send]`、`[sdk/transport]`、`[sdk/diagnosis]`、`[sdk/feedback]`、`[sdk/event]` 的故障前后日志。
- 默认真机点动反馈源为 `/aubo_i5/aubo_hw_node/raw_joint_states`。检查原始反馈，不用持续重发缓存的展示话题代替硬件采样新鲜度。
- `Missing joint1, joint2` 可能涉及夹爪关节，需与机械臂六轴反馈和 MAC 欠载分别定位。
- `capture_cartesian_jog_sdk.sh` 会启动真机 SDK 诊断入口，可能上电、松刹车；脚本不自动请求运动，但不是纯只读检查。strace 会扰动调度，结果用于定位等待阶段。

## 4. 移动底盘常见问题与防范

### 4.1 串口、电机与速度执行

| 现象 | 排查与处理 |
| --- | --- |
| 串口不存在 | 查 USB 枚举、供电、线缆和 udev；优先 `/dev/serial/by-id/…` 或经核实的 `/dev/wheeltec_controller` |
| Permission denied | 用 `ls -l`、`id` 查设备所属组与当前权限；通过系统设备权限规则修复，不长期用全局可写权限替代 |
| 串口被占用 | 用 `fuser` 定位占用；PC 驱动、串口监视器不能同时抢占设备 |
| 有发送无反馈 | 核对波特率、固件帧格式、BCC、接线、控制板模式；区分串口打开和协议正常 |
| 正负方向相反 | 低速逐轴核对车体前进和转向、编码器方向、电机接线；不要只反转上层速度掩盖反馈错误 |
| 发速度但车不动 | 查急停、电机使能、电池、电机驱动故障、最小可运动速度及最终 `/cmd_vel` |
| 松手仍行驶 | 查其他速度发布者、回调排队、PC 超时与 MCU 失联停车；核实现场速度已归零 |
| USB 反复掉线 | 同步记录内核 USB 事件、电压与串口错误；检查接头、供电、干扰与电机启动影响 |
| 重连后突然移动 | 当前驱动重开端口先发零，但后续上游命令仍可执行；需在任务/授权层阻断旧意图 |

当前 PC 默认 `serial_timeout_ms=200`、`serial_reconnect_interval=1.0 s`、`cmd_vel_timeout=0.5 s`。速度看门狗在串口读取和 `spinOnce()` 所在循环检查，因此 0.5 s 不是严格的最坏停车时间；串口阻塞和回调处理会增加延迟。

代码当前直接把速度乘 1000 转为 `short`，未在该发送回调中完整校验 NaN/Inf 和车辆速度范围，也未核验 `write()` 的返回字节数。建议补充输入有限值、车型限速、编码范围、短写处理和统计；这是待改进项，不是已具备能力。

### 4.2 里程计、IMU 与 TF

目标链通常是 `map → odom → base_footprint → base_link → 传感器/机械臂`，实际名称须服从所选启动配置。WheelTec 原始驱动默认里程计 frame 为 `odom_combined`，移动导航配置使用 `odom`；应核对融合节点及 remap，不能只修改字符串制造一条假链。

| 现象 | 优先检查 |
| --- | --- |
| 直行里程成比例偏差 | 轮径/编码器参数、打滑、`odom_x_scale`，用外部实际测量作参考 |
| 转向角度偏差 | 轮距、左右轮差异、IMU 零偏、正负向角速度比例 |
| 地图重影/墙面拉扯 | 里程计、雷达外参、时间戳、安装振动和打滑，最后再调建图算法 |
| TF extrapolation | 数据时间戳、主机时钟、TF 发布频率、消息延迟；不要首先放大容忍时间 |
| TF_REPEATED_DATA/位姿跳动 | 同一变换是否多源发布、重复扫描时间戳、定位重置或时钟跳变 |
| 静止仍显示角速度 | IMU 预热、静止零偏、量程换算、坐标方向；滤波协方差不能代替校准 |

同一条 TF 边只保留一个发布权威。真机检查 `/use_sim_time`，不能在没有 `/clock` 时依赖仿真时间驱动看门狗。多机应校时；设备失联计时优先考虑单调时钟，与 ROS 消息采样时间分开设计。

### 4.3 激光、代价地图与导航

| 现象 | 排查与处理 |
| --- | --- |
| 有前雷达但没有 `/scan` | 移动导航默认合并 `/front/scan` 和 `/rear/scan`，`require_both_scans=true`；先确认两路及外参 |
| RViz 激光错位 | 检查原始 frame、安装平移/旋转、扫描方向；合并不能只拼接 ranges |
| 规划有路径但不走 | 比较 `/cmd_vel_raw` 与 `/cmd_vel`，查激光过滤器 blocked、运动锁、过期数据及驱动 |
| 门口过不去 | 先量真实外廓和定位误差，再看 footprint、padding、inflation，不能缩小模型来“通过” |
| 左右摆动或转圈 | 查速度死区、定位抖动、路径代价、角速度上下限、控制频率及恢复行为 |
| 到目标附近反复调整 | 核对实际定位精度与目标容差；还应检查最低转速是否过高、底盘是否有残余滑行 |
| 障碍移走仍堵住 | 查 clearing、raytrace、传感器更新、TF 与观测范围；先查观测链再清图 |
| 导航突然停车 | 查原始扫描是否中断、过滤器接收超时、障碍阈值、锁状态和地图占用 |

当前激光过滤器以车体系扫描做平面判断；默认输入 `/scan` 来自合并器并位于 `base_footprint`。换接单雷达时，必须先保证坐标与安装偏移正确。当前新鲜度主要按本地接收时间判断，持续重发旧数据仍可能被视为新鲜；建议补充 header 时间、帧推进、frame 与有效覆盖检查。

当前 `/sorting/base_locked` 是 Bool 锁，过滤器没有锁持有者心跳/租约超时；锁发布者退出后的恢复与授权需另行设计。该软件过滤器仅覆盖可见的二维激光几何，未覆盖高处障碍、机械臂完整空间外廓和所有动态制动情况。

## 5. 调参方法

### 5.1 共用步骤

1. 保存基线：启动入口、软件/固件版本、实际参数、负载、地图和测试场地。
2. 明确单个指标：如直行比例误差、最大跟随误差、停止距离、到位时间或调用耗时。
3. 一次只改一类参数；使用相同输入、速度、路径和环境，重复测试并记录离散程度。
4. 从低速、短距离开始，验证静止、启停、反向，再扩大工作范围。
5. 检查副作用：更平滑可能响应更慢，更密采样可能增加计算耗时，更大缓冲可能增加停止延迟。
6. 保存有效配置与回退版本；确认启动后实际加载的参数，而非只看 YAML。

运行值用 `rosparam get /节点命名空间/参数` 核验。`rosparam set` 修改参数服务器不代表节点重新读取；点动参数当前在启动时读取。导航与跟随中哪些参数支持动态调整，以实际节点接口和 cfg 为准。

### 5.2 机械臂参数

来源：[cartesian_jog.yaml](../aubo/aubo_ros_control/config/cartesian_jog.yaml)。

| 参数 | 当前配置 | 调整原则 |
| --- | --- | --- |
| `max_linear_velocity` | 0.10 m/s | 面板默认选择 10 mm/s；先用低速验证方向和停止，限制上限不代表实际速度 |
| `joint_velocity_limits` | 前三轴 0.25，后三轴 0.35 rad/s | 受模型和实际负载约束；检查是哪一轴导致整体限速 |
| `joint_acceleration_limits` | 前三轴 0.60，后三轴 0.80 rad/s² | 减小通常使启停更缓，也可能增加停止时间/距离 |
| `joint_jerk_limits` | 前三轴 8，后三轴 12 rad/s³ | 降低以缓和加速度变化；同时核验制动尾段可在预算内停稳 |
| `command_timeout` | 0.15 s | 按输入周期和抖动选取；放大将推迟失联检测 |
| `feedback_timeout` | 0.15 s | 先查反馈年龄和中断原因，再决定阈值，不用放宽来代替恢复反馈 |
| `max_following_error` | 0.12 rad | 先查延迟、排队、方向和速度；增大降低偏差检测敏感度 |
| `joint_limit_margin` | 0.08 rad | 保留限位裕量并结合实际制动，不能靠缩小裕量处理越限 |
| `dls_lambda` | 0.02 | 增大一般抑制逆解放大，也增加运动偏差；结合关节速度和 TCP 误差比较 |
| `singularity_slow/stop` | 0.06 / 0.008 | 依赖当前雅可比及模型定义，不是通用距离；优先选择远离奇异的初始姿态 |
| `collision_resolution` | 0.002 rad | 减小增加采样密度与耗时；检查计算预算及薄障碍遗漏风险 |
| `home_joint_velocity` | 0.10 rad/s | 降低可减缓回 home；仍受各轴速度、加速度、jerk 限制 |
| `home_timeout` | 90 s | 根据目标距离和实际限速设定；先查运动为何未完成 |

直接 SDK 专用流控：

| 参数 | 当前值与代码边界 | 取舍 |
| --- | --- | --- |
| `sdk_mac_buffer_target` | 60 标量；点动只接受 24～60 的 6 倍数 | 小缓冲对阻塞敏感，大缓冲增加前瞻；不能直接设为 120 |
| `sdk_mac_buffer_limit` | 360 标量；须不小于 target、不超过 396，且为 6 倍数 | 是保守积压硬上限，不是正常供点目标 |
| `sdk_diagnosis_timeout` | 0.15 s；允许 `(0,0.5]` | 放大仅延后故障检测，不能让同步下发变快 |
| 点执行周期 | 固定 5 ms | 不能通过改变 ROS 发布频率改变控制柜消费周期 |

`collision_class`、真实机器人检查、急停状态应按控制柜与工具配置核对，不能作为“解决卡顿”的调参入口。

### 5.3 底盘里程计标定

先确认轮胎、载荷、地面和编码器方向一致，再校正比例。当前 `odom_*_scale` 修改的是接收速度及其积分结果，不直接校正电机控制输出。

直线实验：测量实际距离 `L_real` 与原始里程计距离 `L_odom`，前进和后退分别重复，估计：

```text
新的 odom_x_scale = 原 odom_x_scale × L_real / L_odom
```

转向实验：使用外部参考累计转角，避免把 [-π,π] 的包络 yaw 直接相减；左右转分别估计：

```text
新的 odom_z_scale_positive = 原值 × |实际左转角| / |里程计左转角|
新的 odom_z_scale_negative = 原值 × |实际右转角| / |里程计右转角|
```

不要使用已被 AMCL 地图校正后的位姿作为原始轮式里程计的唯一参考。非比例误差、速度相关误差、左右转明显不一致时，继续检查轮距、打滑、电机闭环和 IMU，而非反复乘系数。差速底盘不通过 `odom_y_scale` 制造横移能力。

### 5.4 导航与停车参数

以下为 `aubo_mobile_navigation` 配置；厂家 `turn_on_wheeltec_robot` 的导航配置是另一套入口。

| 参数组 | 当前值举例 | 方法 |
| --- | --- | --- |
| DWA 限速 | `max_vel_x=0.30`，`max_vel_theta=0.80` | 先以低速确认路径与制动；与底盘实际能力一致 |
| DWA 加速度 | `acc_lim_x=0.50`，`acc_lim_theta=1.00` | 用实测加减速能力约束，不能让规划器假设不存在的制动能力 |
| 最小速度 | `min_vel_trans=0.02`，`min_vel_theta=0.08` | 太低可能克服不了静摩擦，太高可能目标附近过冲；分别实测 |
| 目标容差 | `xy_goal_tolerance=0.04 m`，`yaw_goal_tolerance=0.06 rad` | 结合定位精度与作业需求，不能靠无限收紧获得抓取精度 |
| 采样与预测 | `vx_samples=15`，`vtheta_samples=30`，`sim_time=2.0 s` | 增大可能提高候选覆盖，也增加耗时；与控制循环预算一起测 |
| 路径代价 | path=32，goal=20，obstacle=0.05 | 在外廓、定位、观测正确后，再逐项比较贴路径、趋近目标和避障行为 |
| 代价地图 | 半径 0.35 m、padding 0.01 m、膨胀 0.50 m | 当前含仿真尺寸假设；实机按全部外廓、机械臂运输姿态与载荷重新测量 |
| 控制与地图更新 | controller 10 Hz、local costmap 10 Hz | 查实际耗时是否满足周期；单纯加频率可能加重拥塞 |
| AMCL | 500～2000 粒子，`update_min_d/a=0.08` | 先完成里程计和雷达外参；再调运动噪声、粒子数和更新门槛 |

最终值受 launch 覆盖和可选 navigation profile 影响，应读取参数服务器确认，不能只依据配置文件的加载注释推断。

激光停车层当前公式为：

```text
前/后停车阈值 = 基础距离 + 反应时间 × |v| + v² / (2 × 最大减速度)
```

默认基础距离 0.35 m、反应时间 0.25 s、最大减速度 0.8 m/s²。以 `v=0.30 m/s` 代入得约 0.481 m，这是过滤器公式结果，不是已验证的实际停止距离。

反应时间应覆盖感知、通信和调度延迟；可用减速度应按最不利负载、地面实测保守选取。另有半宽 0.30 m、侧向余量 0.12 m、旋转净空 0.48 m、障碍簇 3 点、紧急距离 0.18 m。代码对倒车、原地旋转和低速转弯分别判断；这些值必须结合安装几何和传感器覆盖复核，不能为消除误停而直接关闭保护。

### 5.5 跟随与 PID

来源：[follower.yaml](../aubo_mobile_robot/aubo_mobile_follower/config/follower.yaml) 与 [pid.py](../aubo_mobile_robot/aubo_mobile_follower/src/aubo_mobile_follower/pid.py)。

1. 先稳定目标观测：激光点簇和目标距离、颜色 HSV/面积、巡线 ROI/掩膜；观测跳变时先修感知。
2. 从 `Ki=0、Kd=0` 开始调 Kp，低速观察响应，出现持续摆动后减小 Kp。
3. 需要抑制过冲时再少量加入 Kd；噪声大时结合微分滤波，避免把测量噪声放大为转向。
4. 只有稳定偏差确实存在时再加入 Ki，设置积分限幅与抗饱和；目标丢失或模式切换时核对积分复位。
5. 最后调整速度限幅、死区和恢复死区，兼顾小误差停车与重新起步，防止来回切换。

当前 PID 使用测量时间，重复/乱序时间戳不会继续积分或更新微分。微分滤波为 `D=alpha×新微分+(1-alpha)×旧微分`，因此 alpha 越大越跟随新变化、滤波越弱。当前默认 alpha=0.25。

跟随控制频率默认 15 Hz、传感器超时 0.5 s，并要求 arm_ready；启用参数不等于所有 launch 都已建立完整机械臂运输姿态确认，应核对实际就绪发布者。激光跟随的 `target_distance=1.0 m` 与 `min_target_distance=0.35 m` 也不能替代停车层制动验证。

## 6. 移动底盘与机械臂联合调试

### 6.1 建议的顺序任务状态机

```text
待机/禁用
→ 验证机械臂运输姿态
→ 导航
→ 取消其他底盘指令源并锁定底盘
→ 通过新鲜反馈确认底盘连续停稳
→ 机械臂作业
→ 确认机械臂停稳并回运输姿态
→ 显式释放底盘运动授权
```

当前 `nav_arm_coordinator.py` 实现的是“机械臂预备姿态 → 导航成功 → 机械臂动作”的顺序协调，不是全身规划。该节点在导航返回 SUCCEEDED 后直接进入后续机械臂阶段，没有独立的底盘停稳连续确认与底盘锁闭环；上面的完整状态机属于建议补充。

停稳确认应使用新鲜里程计/关节速度，在连续时间窗内满足速度阈值；反馈无效时保持未确认。阈值与持续时间需要按噪声、载荷和地面实测设置，不能把某个示例值当作安全保证。

### 6.2 联调故障表

| 故障 | 处理与恢复条件 |
| --- | --- |
| 导航失败/超时 | 取消任务并停止底盘，不进入后续机械臂动作；等待最终状态和反馈 |
| 底盘未停稳 | 保持机械臂动作禁止，查残余命令、坡面滑行和制动能力 |
| 机械臂故障 | 维持底盘锁定，确认机械臂实际状态和外廓，再决定人工恢复 |
| 定位丢失/跳变 | 暂停地图坐标导航；重新定位后重新校验目标，不沿用旧位姿继续作业 |
| 相机外参错误 | 停止执行抓取目标，核对相机光学系、base/tool 链和标定适用安装 |
| 抓取位置随底盘位置漂移 | 查底盘定位、停稳、相机固定方式和 map/base 变换采样时刻 |
| 任务节点重启 | 重新读取硬件实际状态、取消或核对残留 action；不自动恢复旧阶段 |
| 锁定状态和任务状态冲突 | 保留禁止运动状态，检查锁发布者与任务持有者，禁止靠发布 false 盲目解锁 |

二维 costmap 不会自动包含伸出机械臂、工件及高处障碍的全部空间；机械臂 PlanningScene 也不会自动获得地图和所有实物。联合运行前分别核对底盘外廓和机械臂场景。视觉外参入口见 [眼在手外 RGB-D 说明](../aubo_mobile_robot/EYE_TO_HAND_RGBD.md)。

## 7. 故障注入与验收记录

先在离线/仿真验证，再在具备现场停车条件的低速实机环境复核。表中是待执行的验收项目，不代表当前硬件已通过。

| 场景 | 期望行为与应记录证据 |
| --- | --- |
| 错误 CRC/BCC、截断帧、噪声、分包粘包 | 不执行坏帧，解析恢复，不被无效输入刷新有效性 |
| 重复/乱序/旧会话遥控帧 | 不重复执行离散动作，不恢复旧授权；分别核对应答和控制状态 |
| MCU 重启但串口未断 | 未校准/输入无效触发停止，新会话只建基线，重新显式使能 |
| PC 进程崩溃/PC 掉电 | 下位机独立失联停车；记录实际停止时间、距离，不能只测正常退出 |
| 断网/拔串口/长时间无反馈 | 停止新指令并报告故障；反馈缺失不伪造停稳或到位 |
| 反馈持续重发旧值 | 通过时间戳/样本推进检测陈旧；当前不足处单独记缺陷 |
| SDK 下发失败/迟到返回 | 不盲目重发；保存批次和在途状态，故障不会被迟到成功清除 |
| CPU 高负载/诊断慢/点生成慢 | 输出周期异常被识别，记录各阶段耗时，禁止延迟后追赶补发 |
| 激光单路失效/过滤器退出 | 核对合并输出、停车层和底盘看门狗的全过程；恢复后不沿用旧任务意图 |
| 松手、反向、取消 home | 实际减速和最终状态一致；测量停止延迟、距离及最大跟随误差 |
| 两个指令源同时请求控制 | 按既定仲裁拒绝或切换，停车不被另一来源覆盖 |
| 导航结束但底盘仍滑行 | 机械臂动作保持禁止，直到新鲜反馈连续确认停稳 |

已有离线/仿真测试入口列于 [点动说明](../aubo/aubo_ros_control/CARTESIAN_JOG.md) 和 [串口协议说明](../aubo/aubo_remote_bridge/CARTESIAN_SERIAL_PROTOCOL.md)。历史文档可能对应不同实现版本，记录结果时必须同时记录 commit 或工作区差异，不将历史“通过”视为当前版本和实机通过。

每次试验至少记录：

```text
日期/人员/场地：
软件版本及未提交差异、SDK/固件版本：
车型、工具、载荷、电池状态、地面：
启动入口与全部覆盖参数：
初始姿态/定位/任务阶段：
输入操作及故障注入时刻：
发送批次/返回码/调用耗时/反馈年龄/队列积压：
停止检测时刻、实际停稳时刻、停止距离：

```

```bash
rosservice call /aubo_i5/controller_manager/list_controllers "{}"
```

多机 ROS 1 场景要检查所有主机之间的地址可达与节点协商，master 端口可达不等于话题数据可达。`geometry_msgs/Twist` 本身没有时间戳和有效期；本地收到它不能证明上游意图仍新鲜，跨网络任务建议在进入最终速度出口前补充有效期和授权检查。

可按所用后端采集下面的关键话题，`/tmp` 仅为示例输出目录：

```bash
rosbag record -O /tmp/robot_debug.bag \
  /rosout /tf /tf_static /odom /imu /scan \
  /cmd_vel_raw /cmd_vel /sorting/base_locked \
  /cartesian_jog/state /aubo_i5/aubo_hw_node/raw_joint_states
```

`rostopic hz` 只能说明发布频率，还要检查采样时间、帧内容是否推进及实际年龄。rosbag 用于复现时避免把速度/action 指令直接回放到真机控制话题；先在隔离 ROS 环境分析。采集完成后同时保存实际参数和启动日志，避免缺少配置上下文。
