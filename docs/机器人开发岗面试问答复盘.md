## 二、项目架构、队列与轨迹控制

### Q1：用一分钟介绍机械臂视觉分拣系统，你会怎么组织？

**参考回答：** 我会按感知、决策、控制和执行四层介绍。感知输出带时间戳和坐标系的目标位姿；任务状态机决定观察、接近、抓取和放置；长距离运动交给规划，局部修正交给视觉伺服；执行层检查指令和反馈并管理 SDK 通信。重点讲清我负责哪一层、解决了哪个具体问题，以及用什么日志和实验验证，避免把整个仓库的功能都算作个人成果。

**常见追问：** 你本人写了哪些模块？一次完整动作经过哪些话题、服务和线程？失败时谁负责停止？

### Q2：生产者和消费者是谁？为什么需要不同频率？

**参考回答：** 在视觉伺服队列路径，控制回调生产关节位置点，输出端消费并发送。视觉更新较慢，执行端需要更密的采样，因此控制周期内做子步积分生成输出点。当前代码默认控制 50 Hz、输出 200 Hz，即名义 20 ms 控制周期对应约 4 个 5 ms 点。直接 SDK 点动则采用按需生成回调，不能把所有后端都描述成相同队列模型。

**追问要点：** SDK 可能一次发多个点，所以“200 Hz 点执行”不等于“每秒调用 SDK 200 次”；还要区分传感器、反馈、控制、输出与控制柜消费频率。

### Q3：原子读写索引加 std::queue，能实现无锁 SPSC 吗？

**参考回答：** 不能据此保证线程安全。`std::queue` 的 push/pop 会修改底层容器及共享内部状态，两个索引原子化并不会保护这些操作。典型有界 SPSC 使用预分配环形数组，生产者写独占槽位后发布写索引，消费者读取后发布读索引，并明确空满判定、对象生命周期和内存序。当前仓库实现是 mutex 加 deque，我不会把它称为无锁队列。

### Q4：SPSC 中 acquire/release 具体保护什么？

**参考回答：** 生产者先写槽位，再对写索引做 release store；消费者通过 acquire load 观察到该发布后，才读取完整槽位。消费者释放读索引也需要与生产者复用槽位建立对应关系。重点是建立先行关系，不能认为 relaxed 原子索引自动发布普通内存。具体实现还需证明回绕、满队列和析构不会发生并发访问。

**追问要点：** 无锁不等于硬实时；原子类型是否 lock-free、缓存竞争、调度和动态内存分配都影响延迟。

### Q5：队列满时应丢旧指令还是阻塞？

**参考回答：** 取决于数据语义。完整规划轨迹不能随意丢中间点，应限流或暂停上游；视觉连续修正更重视新鲜度，可以有界保存最新意图，但跳过旧点后必须检查输出连续性。当前队列满时丢最旧点，消费边界仍需限速限加速度；不能直接把任意新位置瞬间发送给机械臂。

### Q6：如何根据控制柜缓冲做流控？

**参考回答：** 先确认缓冲量的单位，是关节标量数还是六轴点数，再结合消费周期计算前瞻时间。当前直接 SDK 点动默认首批 10 点，之后每 20 ms 补 4 点，诊断异步运行。发送前预留额度，把在途发送和旧诊断未覆盖的点保守计入积压；只有有效诊断才能回收空间，不按经过时间猜测已经消费。

**项目边界：** 名义目标 60 标量即 10 点、50 ms；硬上限 360 标量即 60 点、300 ms。模型依赖 SDK 接受和诊断采样假设，不是硬实时证明。

### Q7：水位控制如何避免震荡？通信卡顿如何恢复？

**参考回答：** 通用水位控制可以使用上下阈值形成滞回，并限制批量、保留安全余量，避免同一阈值附近频繁切换。通信卡顿后必须先判断命令是否已接受、缓冲是否仍有效、实际反馈在哪里，不能直接追赶补发。当前直接 SDK 故障会锁存停流，不自动续跑；恢复要重新确认状态和授权，水位滞回只是可选设计思路。

### Q8：五次多项式为什么能保证位置、速度和加速度边界？

**参考回答：** 单关节五次多项式有六个系数，可由起终点的 q、dq、ddq 六个条件求出。多段轨迹只有在相邻段共享节点处的这些边界一致时，才具有位置、速度、加速度连续性；它一般不保证 jerk 连续，也不自动保证区间内部不超限。

```text
q(t) = a0 + a1 t + a2 t² + a3 t³ + a4 t⁴ + a5 t⁵
```

### Q9：轨迹没有速度或加速度时，边界条件怎么取？

**参考回答：** 先检查规划和时间参数化结果，而不是假设字段一定缺失。如果只有位置，可以按控制器支持的策略插值，或者重新时间参数化以获得一致的速度、加速度。不应无条件把所有中间点速度和加速度都设零，否则机器人可能每点都启停。数值差分能估计导数，但要处理时间间隔、噪声和连续性，再复核约束。

**追问要点：** ROS 1 JTC 的样条实现按输入边界信息选择插值阶次，不能仅凭类名就断言每段均采用完整五次条件；需要查看实际消息和控制器实现。[ROS 1 JTC 源码](https://github.com/ros-controls/ros_controllers/blob/noetic-devel/joint_trajectory_controller/src/joint_trajectory_controller.cpp)。

### Q10：关节空间与笛卡尔空间插补有什么区别？

**参考回答：** 关节空间插补直接约束关节运动，计算相对简单，但 TCP 路径通常不是直线。笛卡尔插补先规定末端路径，再连续求逆解，需要处理多解、奇异和关节约束。抓取接近段若要求沿工具轴直线运动，就需要明确笛卡尔约束；仅做关节平滑不能证明末端路径正确。

### Q11：规划模式切到视觉伺服，停稳就够了吗？

**参考回答：** 停稳是重要条件，还要确认前一执行目标结束、旧队列和控制柜残余命令处理完成、控制权已移交，并用新鲜反馈初始化伺服状态。若把积分位置直接设成旧目标或把速度初始化错，仍可能跳变。动态切换则需要连续交接位置、速度、加速度，难度更高；当前应明确采用哪种交接方案。

### Q12：SDK 返回成功，如何证明机械臂实际执行正确？

**参考回答：** 我把证据分成合法指令、调用结果、控制柜接收和实际反馈四层。发送前查单位、顺序、有限值与运动约束；调用后记录返回码和耗时；观察 MAC 缓冲；最后比较新鲜关节反馈和目标，确认误差与速度满足到位条件。成功返回不能替代执行完成反馈。

### Q13：如何分析一次运动卡顿？

**参考回答：** 对同一批次记录生成、锁等待、SDK 调用、诊断和反馈的时间，判断是算不出点、发不出去还是反馈断了。当前直接 SDK 历史记录存在 65.26 ms 和 89.24 ms 同步下发，超过 20 ms 补点节拍，说明仅把诊断移到独立线程没有解决发送调用自身阻塞。下一步要定位等待位置并复测，不能把增大缓冲当作已修复。

## 三、视觉伺服、标定与实验指标

### Q14：PBVS 和 IBVS 的区别是什么？项目属于哪一种？

**参考回答：** PBVS 使用估计出的三维位置或位姿误差闭环，IBVS 直接对图像特征误差闭环，常用图像交互矩阵映射速度。当前项目从目标位姿计算控制误差，再经机器人雅可比求关节速度，属于基于三维位置/位姿的伺服思路。是否使用完整六维误差，要按具体模式和姿态控制开关回答。

### Q15：位姿误差如何变成关节指令？

**参考回答：** 在统一坐标系下计算位置误差和旋转误差，经增益、死区、速度限幅得到期望末端 twist，再用阻尼雅可比逆求 dq，经过关节运动约束后积分生成 q。旋转误差可用旋转矩阵对数映射，不能简单把三个欧拉角直接相减。twist 和雅可比的表达坐标、线速度参考点必须一致。

```text
v_des = K e
dq = Jᵀ (J Jᵀ + λ² I)⁻¹ v_des
q_next = q + dq × dt
```

**追问要点：** 上式按误差定义选择控制符号；完整刚体 twist 换参考点通常涉及伴随变换，不能只旋转线速度和角速度就忽略平移项。

### Q16：雅可比从哪里来？如何验证？

**参考回答：** 当前实现由 URDF 构建 KDL 链，使用关节反馈求正运动学和雅可比。验证时先核对关节顺序与 base/tool 链，再对关节施加很小扰动，用正运动学差分和雅可比预测比较；旋转差分使用一致的旋转误差定义。模型、关节零位或工具坐标错误会直接影响结果。

### Q17：阻尼最小二乘为什么能抑制奇异？代价是什么？

**参考回答：** 雅可比小奇异值方向在普通伪逆里会被放大，DLS 把该方向增益改为 `σ/(σ²+λ²)`，限制关节速度放大。代价是任务跟踪误差增大，尤其接近奇异时；它不能消除不可达方向，也不替代关节限位、碰撞和停止保护。

### Q18：固定阻尼怎么优化为自适应阻尼？

**参考回答：** 可以根据最小奇异值或条件数连续增加阻尼：远离奇异时用较小阻尼，接近阈值时平滑增大，同时缩放任务速度。要处理阈值附近抖动，并比较 TCP 误差、关节速度峰值和控制耗时。六维雅可比还涉及平移与转动的尺度归一化；若未做实际验证，应说这是优化方案，不能说已经实现。

### Q19：目标丢失后，为什么不应一直沿原速度运动？

**参考回答：** 失去观测后，旧速度可能继续把机械臂带向障碍或越过目标，因此策略需要有界。可以先减速保持，只有场景和路径允许时才执行恢复搜索；严重故障直接进入保护。当前眼在手上配置的 coast 时长为零，眼在手外配置停止策略；不同入口不能统一说成沿原速度走 3 秒。

**追问要点：** 丢目标、关节反馈丢失、通信故障是三类事件；不能都依赖同一条“减速后回观察位”逻辑。

### Q20：目标抖动和重识别为什么容易造成往返振荡？

**参考回答：** 如果每次检测都立即切换状态，阈值附近噪声会反复触发跟踪、到位和恢复。可以用误差死区、进入/退出滞回、稳定保持时间和重识别确认窗口抑制。滤波也会增加延迟，所以需要同时测跟踪误差与响应时间，避免一味加大平滑。

### Q21：眼在手上和眼在手外的坐标链怎么写？

**参考回答：** 约定 `T_A_B` 把 B 系坐标变换到 A 系。眼在手上时，`T_base_obj = T_base_tool(q) × T_tool_cam × T_cam_obj`；眼在手外时，`T_base_obj = T_base_cam × T_cam_obj`。前者相机随末端运动，外参固定在 tool 与 camera 之间；后者外参固定在 base 与 camera 之间。具体 base 是否随底盘移动，也必须讲清。

### Q22：easy_handeye 做了什么？采样怎样才有效？

**参考回答：** 它根据机器人运动与标记观测求相机和机器人之间的固定变换，常见形式可写为 AX=XB，但 A、B、X 的方向必须和所选布局一致。采样应覆盖多个位置和充分不同的旋转轴，避免仅平移或单轴小角度运动；停稳采样并保证图像、机器人状态和 TF 对应同一时刻。工具只是求解入口，不保证输入几何与时间正确。

### Q23：如何验证标定结果，而不只是看 RViz 对齐？

**参考回答：** 使用未参与标定的独立姿态和目标，比较变换后的目标位置与可靠真值，报告各轴偏差、三维 RMSE、分位数和最大误差。还要检查不同距离、姿态和画面位置是否有系统性偏差。RViz 适合发现方向或数量级错误，不能单独证明毫米级精度。

### Q24：面试官追问“5.8 mm 怎么测得”，应如何回答？

**参考回答模板：** 先说这是位置误差还是包含角度的位姿指标，再说明参考仪器/夹具、真值坐标系、样本数、测试范围和计算公式。如果没有这些原始记录，我会说明该数值暂时不能作为可复核结果，不把重复定位误差、视觉定位误差和抓取成功率混成同一指标。

```text
单样本位置误差 ei = ||p_est_i - p_gt_i||
平均距离误差 = Σ ei / N
三维位置 RMSE = sqrt(Σ ei² / N)
```

平均误差与 RMSE 不是同一统计量；位置 mm 和姿态 deg/rad 应分别报告，若合并必须明确权重。

### Q25：总误差如何拆解？能直接把误差相加吗？

**参考回答：** 我会分相机内参/深度、检测、外参、时间同步、机器人运动学、TCP 和执行误差，设计隔离实验测各环节。小扰动下可用雅可比做协方差传播；只有独立、零均值等条件成立时才能直接按方差叠加。系统偏差和相关性需要单独分析，不能凭总误差推算各环节百分比。

### Q26：如何证明系统改进有效？

**参考回答：** 固定场景、负载、目标分布和成功标准，做基线与改进方案的重复对照，记录所有尝试、失败和超时，不只保留成功样本。报告定位误差、成功率、动作时长、停止延迟及异常类别。离线、仿真、静止实机和实际运动分别说明；当前实验包的验证状态不支持把整套实物分拣宣称为已通过。

## 四、C++ 并发与资源管理

### Q27：原子变量和互斥锁怎么选？

**参考回答：** 原子适合独立标志、计数和经过证明的并发协议；锁适合多个关联字段的一致更新。六轴位置加时间戳需要同一帧快照，逐个原子读取仍可能得到混合帧。原子不一定更快，也不一定 lock-free；我会先保证正确性，再用竞争和延迟测量决定优化。

### Q28：条件变量如何避免丢通知和虚假唤醒？

**参考回答：** 条件变量通知本身不保存业务状态，等待必须配合同一互斥锁保护的谓词，例如 `wait(lock, predicate)`。醒来后再次检查“队列非空或正在退出”，避免把虚假唤醒当作有数据。退出时设置停止状态并唤醒所有等待者，再 join。当前 `CommandQueue` 虽调用 notify，但 pop 没有 wait，不能称它为已经使用条件变量阻塞等待的队列。

### Q29：shared_ptr 哪些操作线程安全？

**参考回答：** 共享同一控制块的不同 shared_ptr 拷贝可以并发执行所有权操作；同一个 shared_ptr 对象若一边 reset/赋值、一边读取或修改，需要同步。多线程只读同一实例通常没有这个写冲突，但被管理对象自身的读写仍需保护。还要避免用同一个裸指针分别构造两个独立控制块，导致重复释放。[标准库线程安全说明](https://learn.microsoft.com/en-us/cpp/standard-library/thread-safety-in-the-cpp-standard-library?view=msvc-170)。

**追问要点：** 项目是 C++14，可用锁或针对 shared_ptr 的原子自由函数同步发布；不要把 C++20 的 `atomic<shared_ptr<T>>` 直接当作当前可用接口。共享所有权也不代表实时线程适合承担最后一次引用释放。

### Q30：std::move 做了什么？移动后还能用吗？

**参考回答：** `std::move` 是把表达式转换为可供移动重载匹配的右值引用，本身不搬资源；实际是否移动取决于被调用操作，也可能发生拷贝。标准库对象移动后通常有效但状态未指定，具体类型可能有更强保证；可以析构和按约定重新赋值，其他操作要满足前置条件。用户自定义类型的移后契约需看实现。[move 定义](https://eel.is/c++draft/forward)、[标准库移后状态](https://eel.is/c++draft/lib.types.movedfrom)。

**易错点：** `std::move(const_obj)` 通常不能调用接收非 const 右值引用的移动构造；不要断言移动一定清空原对象或一定转移资源。

### Q31：vector 扩容什么时候移动，什么时候拷贝？

**参考回答：** 扩容会申请更大连续空间并迁移原元素，旧地址和迭代器失效。常见实现对已有元素采用类似 move_if_noexcept 的策略：移动不抛异常时优先移动；移动可能抛异常且可拷贝时优先拷贝以维持异常保证；不可拷贝时也可能只能移动，失败时保证受限。不能说只有 noexcept 才会移动，扩容倍率也不是标准固定值。[move_if_noexcept](https://eel.is/c++draft/forward)、[vector 异常与失效规则](https://eel.is/c++draft/vector.modifiers)。

### Q32：如何降低实时路径中的 C++ 延迟抖动？

**参考回答：** 预分配内存，限制容器容量和每周期工作量，避免控制线程频繁分配、同步日志和不可控 I/O；共享锁只做快照复制，不覆盖 SDK 调用。用 RAII 管理线程和连接，先停止工作再释放回调关联对象。所有优化都要测执行时间、锁等待和调度间隙，而非只看平均 CPU。

### Q33：如何避免死锁和线程退出挂住？

**参考回答：** 固定锁顺序，减少嵌套锁，不在持锁期间调用可能反向回调自己的外部接口。退出时先标记停止、唤醒等待者并阻止新任务，再等待工作线程结束，最后释放连接。join 不能在对方退出必须获得的锁内执行；SDK 调用若没有可用超时，还需承认退出时长无法严格保证。

## 五、ROS 工程实践

### Q34：Topic、Service、Action 分别适合什么？

**参考回答：** Topic 是发布订阅，适合持续数据和状态；Service 是请求响应，适合短操作和查询，客户端调用通常阻塞等待响应；Action 面向较长任务，提供目标、反馈、结果与取消请求。它们都不自动保证业务实时性和执行完成语义，Action cancel 也需要服务端实现处理与反馈。

**易错点：** Topic 可以多发布多订阅，不能只说一对多；Service 不意味着系统只能有一个客户端，调用成功也不代表机械动作完成。

### Q35：AsyncSpinner 增加线程后，哪些回调会并发？

**参考回答：** 它让回调队列由多个线程处理，不同订阅、服务和定时回调可能并发，因此共享状态要保护。同一个订阅默认仍按顺序一次执行一个回调，显式允许并发才可能重叠。当前视觉伺服入口为 3 线程，硬件入口为 2 线程；点动还使用独立反馈队列，不能说开 4 线程就解决所有阻塞。[roscpp SubscribeOptions 源码](https://github.com/ros/ros_comm/blob/noetic-devel/clients/roscpp/include/ros/subscribe_options.h)。

### Q36：话题频率正常，为什么仍可能用到旧数据？

**参考回答：** 上游可能不断重发缓存，或订阅队列积压，发布频率并不等于采样新鲜度。应检查 header 采样时间、帧推进、接收年龄以及回调延迟，控制输入使用有界队列和明确有效期。`Twist` 没有 header，跨网络传递速度时还需要在入口补充有效期和授权约定。

### Q37：ROS 时间、系统时间、单调时钟如何选择？

**参考回答：** ROS 时间用于与传感器消息和 TF 对齐，但仿真暂停或时钟跳变会影响其推进；本地超时与耗时统计通常使用单调时钟。多机采样时间还要校时，不能用接收时间替代真实采样时间。真机误设 use_sim_time 且没有 clock，可能让依赖 ROS 时间的逻辑失效。

### Q38：TF 报错怎么排查？

**参考回答：** 先核对 frame 名称、父子关系和是否多源发布，再查消息时刻能否取得变换以及各主机时钟。静态外参、动态关节状态和定位变换职责要分清。外推错误优先查延迟与时间，不首先放大 tolerance；TF 能连通也不代表标定几何正确。

## 六、嵌入式实时控制与通信

### Q39：1 ms 中断如何证明没有超时？

**参考回答：** 不只靠代码短，而是建立最坏执行预算，并测包括高优先级中断抢占在内的延迟。可用 GPIO 翻转加逻辑分析仪，或用支持的周期计数器统计峰值和超时次数。中断里保留有界控制计算，串口解析、阻塞发送、打印和动态分配移到主循环或任务；还要核对 ADC/编码器采样和 PWM 更新时序。

### Q40：UART 加 DMA 如何处理粘包、断帧和校验失败？

**参考回答：** DMA 只负责搬字节，不理解协议帧。上层用环形缓存和解析状态机按帧头、长度、校验、帧尾处理任意分块，同时处理 DMA 回绕、缓存溢出和半帧超时。IDLE 可提示本次接收间隙，但不能假设一次 IDLE 就是一整帧。校验失败后按可恢复策略重新找帧头，不用坏帧刷新看门狗。

### Q41：异或校验够不够？CRC 能防止旧命令吗？

**参考回答：** BCC 简单但检错能力有限，CRC 对指定错误模式有更强检测能力，具体取决于多项式和帧长。两者都不负责旧帧、重复动作和身份认证，需要会话、序号、有效期和请求去重。当前底盘使用 BCC，机械臂遥控使用 CRC-16 与 session/request_id，不能混称为同一种保障。

### Q42：位置式和增量式 PID 有什么区别？

**参考回答：** 位置式直接计算控制输出 u，增量式计算变化量 Δu 并与历史输出合成。在固定采样周期和相同离散化、无饱和等条件下，两者可等价；实际差异主要体现在状态保存、限幅、积分和模式切换。不能仅凭名称断言增量式没有积分饱和、计算一定更快或容错一定更好。

```text
位置式：u[k] = Kp e[k] + Ki Ts Σe[i] + Kd/Ts (e[k]-e[k-1])
增量式：Δu[k] = Kp(e[k]-e[k-1]) + Ki Ts e[k]
                  + Kd/Ts(e[k]-2e[k-1]+e[k-2])
        u[k] = u[k-1] + Δu[k]
```

**追问要点：** 饱和后内部累计输出若与执行器实际输出不一致，仍可能出现 windup；可使用条件积分、回算或输出跟踪等抗饱和方法。[MathWorks 抗积分饱和说明](https://www.mathworks.com/help/simulink/slref/anti-windup-control-using-a-pid-controller.html)。

### Q43：速度前馈怎么叠加？它能代替反馈吗？

**参考回答：** 先说明控制层级。若是位置外环生成速度指令，可加入期望轨迹速度前馈；若是电机速度环输出 PWM/力矩，则前馈通常是速度、加速度和摩擦模型对应的驱动力，不是把速度数值直接加到 PWM 上。最终输出等于同单位的前馈与反馈之和，再做限幅和抗饱和；前馈不能修正未知扰动，需要反馈补偿。

### Q44：PID 如何调参，为什么通常先不加积分？

**参考回答：** 先确认方向、量纲、采样周期、执行器限幅和传感器噪声，再低速从 P 开始，逐步获得足够响应且无持续振荡；需要抑制过冲时加少量 D 和滤波，稳定偏差确实存在时再加 I。积分会在饱和或堵转时积累，必须带抗饱和；一次只改一类参数并记录超调、稳定时间和控制量峰值。

## 七、移动机器人与联合系统追问

### Q45：如何标定底盘里程计？

**参考回答：** 用外部测量分别做直线和左右转重复实验，先查轮径、轮距、编码器方向与打滑，再校正比例。新比例可按原比例乘“真实运动量/里程计运动量”，但不能用 AMCL 已校正位姿替代独立真值。转角要累计展开，正负向可分别评估；比例修正不能解决非线性或速度相关误差。

### Q46：map 和 odom 为什么要分开？

**参考回答：** odom 通常提供局部连续但会漂移的运动估计，map 提供全局定位参考，定位修正通过 map 到 odom 表达，可能发生跳变。局部控制重视连续性，全局任务重视地图一致性。同一条变换只保留一个发布权威，避免里程计、融合与定位重复发布冲突。

### Q47：导航有路径但机器人不动，你怎么查？

**参考回答：** 顺着最终执行链检查：move_base 状态与局部轨迹、cmd_vel_raw、激光过滤器、cmd_vel、串口和底盘反馈。原始速度非零但最终为零，就查障碍、数据过期或运动锁；最终非零但底盘不动，就查串口、电机使能、急停和死区。这样能区分算法不产出与下层拒绝执行。

### Q48：导航成功后可以立即启动机械臂吗？

**参考回答：** 还应撤销其他底盘速度来源、锁定底盘，并用新鲜反馈连续确认停稳，再启动机械臂。仅靠 action 成功不能覆盖坡面滑行、其他发布者和通信延迟。当前简单 nav_arm_coordinator 主要实现顺序动作，独立停稳确认与完整锁闭环属于需要补强的部分，不能说仓库所有入口都已做到。

### Q49：安全停车距离如何选？

**参考回答：** 以实际可保证的制动能力和延迟估计基本阈值：基础余量加反应时间内位移，再加制动距离 `v²/(2a)`，同时考虑负载、地面、方向和传感器盲区。使用最不利条件实测复核，不能把规划器加速度上限直接当作真实减速度。机械臂伸出和工件会改变外廓，二维激光也不覆盖所有高度。

### Q50：PC 崩溃或串口断开，谁负责停车？

**参考回答：** 下位机必须有独立的命令有效期或通信看门狗，失联后执行约定的停止。PC 正常运行时可以超时发零，但线断了就无法依赖这帧到达。恢复后应重新确认状态和授权；当前底盘驱动重连先发零，但如果上游继续发旧意图仍可能再动，不能称其天然具备完整重连防自启。

## 八、面试结束前应准备的证据

| 材料 | 最少能回答的内容 |
| --- | --- |
| 一张实际数据流图 | 每个节点、通信接口、指令源和停止责任 |
| 一张线程与时序图 | 哪个线程生产/消费，锁保护什么，频率与耗时如何测量 |
