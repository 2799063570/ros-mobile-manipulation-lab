## 一、项目概览

本项目围绕“移动到达、环境感知和机械操作”这一复合机器人任务链展开。项目以 WheelTec ROS 功能包为学习参考，理解底盘、传感器、TF、SLAM 与导航的数据链路；在此基础上，自主搭建差速移动机器人，并将 AUBO i5 六轴机械臂、双指夹爪、双激光雷达和手部 RGB 相机集成到统一的 ROS 系统中。

系统面向室内固定工位作业场景，能够先完成环境建图、定位与自主导航，再利用手部相机识别红、绿、蓝目标，通过 AUBO i5 六轴机械臂完成抓取和分类放置。

### 核心能力

| 能力模块 | 主要实现 | 输出效果 |
| --- | --- | --- |
| 机器人建模与仿真 | Xacro/URDF、Gazebo 传感器与 `ros_control` 控制器 | 形成可移动、可感知、可规划的复合机器人模型 |
| 建图与定位 | 前后激光雷达融合、GMapping、AMCL、TF 管理 | 生成地图并获得 `map → odom → base_link` 位姿链 |
| 自主导航 | `move_base`、全局与局部代价地图、DWA 局部规划 | 根据工位目标自主规划并驱动底盘到达 |
| 视觉感知 | HSV 颜色分割、轮廓检测、像素射线与平面求交 | 输出目标颜色、像素坐标及 `base_link` 下的三维位置 |
| 机械臂操作 | MoveIt、笛卡尔路径、轨迹控制器与夹爪控制 | 完成预抓取、下降、夹取、抬升和分类放置 |
| 任务编排 | 状态机、ROS 服务与话题、导航与分拣顺序协调 | 实现“导航到工位后自动分拣”的完整流程 |

### 技术栈

`ROS 1` · `C++` · `Python` · `Gazebo` · `RViz` · `MoveIt` · `OpenCV` · `GMapping` · `AMCL` · `Navigation Stack` · `TF` · `actionlib`

## 三、系统组成与软件架构

### 硬件与仿真组成

| 组成 | 配置 | 作用 |
| --- | --- | --- |
| 移动底盘 | 差速驱动底盘和编码器里程计 | 执行速度指令并发布 `/odom` |
| 机械臂 | AUBO i5 六轴机械臂 | 执行 MoveIt 规划后的关节轨迹 |
| 末端执行器 | 双指夹爪和 `tcp_link` | 完成方块夹取与释放 |
| 环境感知 | 前后二维激光雷达 | 融合生成 360° `/scan`，用于建图、定位与避障 |
| 操作感知 | 手部 RGB 相机 | 识别颜色目标并估计桌面位置 |

### ROS 数据流

```text
/front/scan ─┐
             ├─ 双雷达融合 ─ /scan ─┬─ GMapping ── map
/rear/scan ──┘                       ├─ AMCL ────── map → odom
                                    └─ move_base ─ /cmd_vel
                                                       │
                                   odom ← 差速底盘 ←───┘

/hand_camera/image_raw
        │
        ▼
OpenCV 颜色识别 ── 目标三维位置
        │
        ▼
任务协调器 ── MoveIt ── 机械臂轨迹控制器 + 夹爪轨迹控制器
```

主要 TF 链路为：

```text
map → odom → base_footprint → base_link → AUBO 各级连杆 → tcp_link
```

建图时，`map → odom` 由 GMapping 发布；使用已有地图导航时，该变换由 AMCL 发布。二者不能同时运行，否则会产生 TF 冲突。

## 四、移动导航子系统

### 双雷达融合

前、后激光扫描首先变换到 `base_footprint` 坐标系，再生成包含 720 个采样点的 360° `/scan`。融合过程考虑两个雷达的安装位置和朝向，并非简单拼接距离数组。

```text
前后 LaserScan
    ↓
转换到 base_footprint
    ↓
生成 360° /scan
    ↓
GMapping / AMCL / move_base
```

### 建图、定位与导航

| 阶段 | 核心模块 | 结果 |
| --- | --- | --- |
| 环境建图 | GMapping、里程计、融合激光 | 生成并保存 `map.yaml` 和 `map.pgm` |
| 初始定位 | AMCL、静态地图 | 估计机器人在地图中的概率位姿 |
| 路径规划 | `move_base`、全局规划器、DWA | 生成全局路径并进行局部避障 |
| 底盘执行 | `/cmd_vel`、差速驱动 | 跟踪速度指令并更新 `/odom` |

### 工程安全约束

- 导航 footprint 按机械臂收拢状态设置，底盘移动前先将机械臂收回 `home` 或 `down` 安全姿态；
- 机械臂伸展或抓取期间保持底盘静止，避免感知坐标和碰撞边界失效；
- 仿真与实机切换时分别检查里程计、TF 发布者和控制器，避免重复发布坐标变换。

机器人完成定位后接收工位目标位姿，经 `move_base` 规划和底盘执行，到达机械臂能够覆盖工作台的预设作业位置。

## 五、视觉感知与抓取分拣

### 颜色目标定位

```text
手部 RGB 图像
    ↓
HSV 颜色分割
    ↓
轮廓面积与长宽比筛选
    ↓
像素射线与标定桌面求交
    ↓
发布 base_link 坐标系下的目标三维位置
```

当前方案面向目标高度已知、表面平整的桌面场景。节点根据相机内参生成像素射线，并在 `base_link` 坐标系下与标定平面求交。系统对连续 8 帧同色目标坐标求平均，以降低单帧轮廓中心抖动。

### 单个目标的抓放流程

1. 机械臂移动到相机观察位并获取最新识别坐标；
2. 张开夹爪，规划到目标上方的预抓取点；
3. 沿笛卡尔路径下降并闭合夹爪；
4. 抬升目标并移动到相应颜色的分类区域；
5. 下降、释放目标并安全回退。

### 关键工程处理

| 问题 | 处理方式 |
| --- | --- |
| 桌面碰撞 | 在机械臂运动前将 `sorting_table` 加入 MoveIt PlanningScene，并等待场景确认 |
| 识别抖动 | 对连续多帧目标位置求平均，并保留标定偏移参数 |
| 夹爪接触失败 | 调整夹爪闭合目标、运动时间及接触容差，使其符合实体接触特性 |
| 小方块易滑落 | Gazebo 中使用临时固定关节提高仿真稳定性；实机不依赖该插件 |
| 关节越界风险 | 统一 URDF 与 MoveIt 中 `upperArm_joint` 的关节限制，并在启动时校验 |

## 六、完整任务编排

复合机器人采用“先移动、后操作”的顺序协调方式：

```text
机械臂收回安全姿态
    ↓
底盘定位并导航至分拣工位
    ↓
机械臂移动到相机观察位
    ↓
识别红、绿、蓝方块及其位置
    ↓
MoveIt 规划抓取与放置轨迹
    ↓
夹爪完成分类分拣
    ↓
发布最终任务结果
```

任务状态依次为：

```text
STOWING_ARM
→ NAVIGATING
→ AT_WORKSTATION
→ SORTING
→ SUCCEEDED
```

任务协调器不重复实现底层算法，而是复用导航、MoveIt、视觉识别和分拣模块，通过 ROS 服务与状态话题完成启动、停止、超时、失败和结果发布。

### 主要接口

| 接口 | 作用 |
| --- | --- |
| `/cmd_vel` | 底盘速度指令 |
| `/odom` | 轮式里程计 |
| `/scan` | 双雷达融合后的激光扫描 |
| `/move_base` | 底盘导航 action |
| `/hand_camera/image_raw` | 手部 RGB 相机图像 |
| `/sorting/detections` | 颜色目标及其三维位置 |
| `/sorting/state` | 视觉分拣子任务状态 |
| `/nav_sorting/state` | 导航分拣总任务状态 |
| `/aubo_i5_controller/follow_joint_trajectory` | 六轴机械臂轨迹接口 |
| `/gripper_controller/follow_joint_trajectory` | 双指夹爪轨迹接口 |

## 七、验证方式

- 在 Gazebo 中验证机器人模型、传感器、控制器及物理接触；
- 在 RViz 中检查 TF、地图、激光、代价地图、路径及 MoveIt 规划场景；
- 通过调试图像核对目标轮廓、颜色类别、像素中心和定位结果；
- 通过状态话题与 ROS 服务验证任务启动、停止、异常进入 `ERROR`/`FAILED` 和恢复逻辑。

当前实现采用“先移动、后操作”的顺序协调方案，尚未实现底盘与机械臂同时参与的全身运动规划。该设计适合教学验证和室内固定工位任务，也便于分模块调试。

## 八、项目亮点

- **完整性**：覆盖模型、传感器、SLAM、定位、导航、视觉、规划、控制和任务编排；
- **模块化**：导航、感知、分拣与场景任务相互分离，可以独立启动和调试；
- **工程意识**：处理 TF 冲突、碰撞场景、关节限制、夹爪接触容差和任务失败状态；
- **可迁移性**：仿真入口与实机入口分离，关键标定项和安全约束均有明确说明。

## 九、已知局限

- 仿真参数不能直接替代实机标定；
- RGB 单目定位依赖已知桌面高度；
- 导航 footprint 仅覆盖机械臂收拢状态；
- Gazebo 抓取稳定插件仅服务于仿真验证；
- 实机部署需要重新完成地图、雷达外参、相机内外参、工位位姿、TCP、夹爪行程、速度限制、急停和碰撞保护配置。
