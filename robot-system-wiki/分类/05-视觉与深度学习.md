# 视觉与深度学习

视觉链路可分为四层：相机驱动、图像预处理、检测/跟踪、行为控制。调试时逐层验证，避免把“相机无图像”误判为“模型识别失败”。

## 相关包

| 包 | 类型 | 作用 |
|---|---|---|
| `usb_cam`、`astra_camera`、`realsense2_camera` | 驱动 | 发布 RGB、深度或点云 |
| `ros_tensorflow` | 深度学习示例 | 分类、目标检测、手写数字识别 |
| `darknet_ros` | YOLO ROS 封装 | 发布检测框和类别 |
| `wheeltec_yolo_action` | 行为层 | 将 YOLO 结果转换成动作决策与执行 |
| `kcf_track` | 传统视觉 | 对选定目标进行相关滤波跟踪 |
| `simple_follower` | 检测与控制 | 颜色/目标位置驱动底盘 |
| `bodyreader` | 人体感知 | 骨架、关节、姿态和跟随 |

## 图像接口基础

- `sensor_msgs/Image`：原始图像，关注 `encoding`、宽高、步长和 frame。
- `sensor_msgs/CompressedImage`：JPEG/PNG 压缩图像，适合网络传输。
- `sensor_msgs/CameraInfo`：焦距、主点和畸变参数。
- `sensor_msgs/PointCloud2`：深度相机生成的三维点云。

```bash
rostopic list | grep image
rostopic hz /camera/image_raw
rqt_image_view
```

## 项目功能入口

```bash
roslaunch ros_tensorflow ros_tensorflow_classify.launch
roslaunch ros_tensorflow ros_tensorflow_detect.launch
roslaunch ros_tensorflow ros_tensorflow_mnist.launch
roslaunch darknet_ros darknet_ros.launch
roslaunch wheeltec_yolo_action gesture.launch
roslaunch wheeltec_yolo_action dp_drive.launch
roslaunch kcf_track kcf_tracker.launch
```

`wheeltec_yolo_action` 中可按 `drive_collection → drive_decision_node → drive_execution_node` 理解数据采集、决策和动作执行的分工，并检查其自定义 `position.msg`、`CtrlData.msg`。

## 阅读和调试顺序

1. 用 `rqt_image_view` 确认原始图像。
2. 用 `rosnode info` 确认检测节点订阅的话题是否一致。
3. 单独验证推理输出，不启动底盘动作。
4. 检查类别 ID、置信度和坐标定义。
5. 最后启动动作节点并限制最大速度。

## 性能与平台限制

TensorFlow/YOLO 模型、CUDA、cuDNN 和 Python 版本之间耦合较强。仓库说明中的部分功能只面向 Jetson；模型能加载不代表帧率足够用于闭环控制。应记录图像频率、推理频率、端到端延迟、CPU/GPU 占用和内存。

## 实验清单

- [ ] 分别测量相机频率和检测结果频率。
- [ ] 改变光照、距离和遮挡，记录置信度变化。
- [ ] 检查检测框坐标是像素坐标还是归一化坐标。
- [ ] 断开相机或停止检测节点，确认动作节点安全停车。
- [ ] 对比 KCF 和 YOLO：前者需要初始化目标，后者按类别检测。
