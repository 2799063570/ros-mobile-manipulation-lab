# 传感器与驱动

传感器驱动的任务不是“理解环境”，而是把硬件数据稳定地转换成带正确时间戳和坐标系的 ROS 消息。SLAM 失败时，优先检查驱动、时间和 TF，而不是立即修改算法参数。

## 雷达包选择

| 系列 | 包/目录 | 统一输出 |
|---|---|---|
| 思岚 | `rplidar_ros` | `/scan` |
| 乐动 | `ldlidar_14`、`ldlidar_19` | `/scan` |
| 镭神 N10 | `lsn10`、`lsn10p` | `/scan` |
| 镭神 M10/X10 | `lslidar_driver`、`lslidar_x10_driver` | `/scan` |

统一入口是 `turn_on_wheeltec_robot/launch/wheeltec_lidar.launch`，通过 `rplidar_mode` 选择实际驱动。不要同时启动多个驱动向同一个 `/scan` 发布。

```bash
roslaunch turn_on_wheeltec_robot wheeltec_lidar.launch
rostopic info /scan
rostopic hz /scan
rostopic echo -n 1 /scan
```

`sensor_msgs/LaserScan` 最重要的字段是 `angle_min/max`、`angle_increment`、`range_min/max`、`ranges[]` 和 `header.frame_id`。在 RViz 中检查墙面是否笔直、静止时点云是否抖动，以及机器人转动时扫描是否与地图一致。

## 相机与图像链路

| 包 | 用途 |
|---|---|
| `astra_camera` | Astra S、Pro、Dabai、Gemini 深度相机 |
| `realsense2_camera` | RealSense RGB、深度、点云与惯导 |
| `usb_cam` | 普通 UVC RGB 相机 |
| `depthimage_to_laserscan` | 深度图切片转换为二维 `LaserScan` |
| `web_video_server` | 将 ROS 图像通过网页发布 |

统一入口是 `turn_on_wheeltec_robot/launch/wheeltec_camera.launch`，由 `camera_mode` 和 `if_usb_cam` 决定启动组合。

```bash
roslaunch turn_on_wheeltec_robot wheeltec_camera.launch
rostopic list | grep -E 'image|camera|depth|points'
rqt_image_view
```

图像消息需要关注编码（RGB/BGR/深度）、分辨率、帧率、相机内参和 `camera_info`。深度图通常以毫米或米表达，使用前必须确认单位。

## TF 与安装位姿

典型关系是：

```text
base_footprint → base_link → laser
                           → camera_link → camera optical frame
                           → gyro_link
```

传感器在 TF 中的位置和朝向必须等于真实安装位姿。雷达前方方向错误会让 SLAM 地图扭曲；相机 optical frame 应遵循 ROS 约定：Z 向前、X 向右、Y 向下。

## 驱动阅读顺序

1. 对应硬件的 `launch`：设备文件、波特率、IP 和 frame。
2. `package.xml`：厂商 SDK 与系统依赖。
3. 节点初始化：串口/USB/网络连接。
4. 原始帧解析和异常处理。
5. ROS 消息填充、时间戳和发布频率。

## 实验与排错

- [ ] 遮挡雷达某个方向，确认 `ranges[]` 对应角度。
- [ ] 测量一米墙面，确认距离误差。
- [ ] 用 `rostopic hz` 检查频率是否稳定。
- [ ] 移动相机前物体，确认图像延迟。
- [ ] 检查 USB 带宽，避免 RGB、深度、点云全开导致丢帧。

常见问题包括 `/dev` 设备名变化、串口权限、USB 供电不足、IP 冲突、时间戳落后、frame 不存在以及扫描角度被错误屏蔽。
