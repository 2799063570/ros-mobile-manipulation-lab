# 仿真、可视化与多机

Gazebo 模拟物理世界和传感器，RViz 显示 ROS 消息与 TF；两者用途不同。Gazebo 中“看起来在动”不代表 ROS 数据链正确，必须同时检查 `/cmd_vel`、`/odom`、`/scan` 和 TF。

## 两套仿真学习路径

### 精简教学包

[[功能包/simple_diff_robot_gazebo]] 是当前仓库中新建的两轮差速教学包，包含球形万向轮、RGB 相机、二维雷达、Gmapping、AMCL 和 DWA。其文件较少，最适合从零理解完整链路。

```bash
roslaunch simple_diff_robot_gazebo display.launch
roslaunch simple_diff_robot_gazebo gazebo.launch
roslaunch simple_diff_robot_gazebo teleop.launch
roslaunch simple_diff_robot_gazebo mapping.launch
roslaunch simple_diff_robot_gazebo navigation.launch
```

建议阅读顺序：Xacro 尺寸参数 → link/joint → Gazebo 传感器插件 → 差速插件 → launch → costmap/DWA 参数。

### 厂家完整仿真

| 包 | 职责 |
|---|---|
| `wheeltec_description` | 多车型 URDF/Xacro、网格、世界 |
| `wheeltec_gazebo_control` | 控制器和车型相关插件 |
| `wheeltec_gazebo_function` | 建图、导航、键盘控制和地图保存 |

```bash
roslaunch wheeltec_gazebo_function mapping.launch
roslaunch wheeltec_gazebo_function keyboard_teleop.launch
roslaunch wheeltec_gazebo_function map_saver.launch
roslaunch wheeltec_gazebo_function navigation.launch
```

厂家包适合学习复杂项目如何复用真机算法配置，但包含多车型与自定义插件，不应作为 URDF 入门的第一份代码。

## Gazebo 核心概念

- visual：外观，不参与碰撞。
- collision：物理碰撞形状，应尽量简单。
- inertial：质量、质心和惯量，错误会导致抖动或飞散。
- joint：连接关系、轴、限位和阻尼。
- plugin：将 Gazebo 数据连接到 ROS 话题或控制接口。
- `use_sim_time`：让 ROS 节点使用 Gazebo `/clock`。

## 仿真验证

- [ ] `check_urdf`/Xacro 能正确展开。
- [ ] 静止时机器人不下沉、不侧翻、不抖动。
- [ ] 正速度直行，正角速度符合 ROS 逆时针约定。
- [ ] `/odom` 与 Gazebo 实际位姿大致一致。
- [ ] 雷达和相机 frame 与模型安装位置一致。
- [ ] 暂停 Gazebo 时依赖模拟时间的节点同步暂停。

## 多机系统

`wheeltec_multi` 的 `wheeltec_slave.launch` 会启动从车底盘、雷达、地图、AMCL、位姿初始化、TF 监听和避障控制。关键参数包括期望相对位置 `slave_x/slave_y`、速度限制、`multi_mode` 与避障开关。

多机必须解决：

1. 所有机器能访问同一个 ROS Master。
2. 正确设置 `ROS_MASTER_URI` 与各机 `ROS_IP`。
3. 系统时间同步，否则 TF 会报过去/未来外推。
4. 节点、话题和 frame 使用明确命名空间。
5. 每台车只能消费属于自己的 `/cmd_vel`。

## 仿真到真机的差异

仿真通常拥有理想里程计、稳定频率、准确轮径和无限算力。迁移真机时要主动加入噪声、轮胎打滑、传感器盲区、通信延迟、速度/加速度限制和急停策略。
