# 跟随与自主行为

这类功能位于“感知”和“底盘”之间：先从雷达或相机找到目标，再计算相对误差，最后发布 `/cmd_vel`。与导航不同，跟随通常没有完整静态地图，而是不断对当前目标作局部反应。

## 包与功能

| 包 | 功能 | 主要输入 | 主要输出 |
|---|---|---|---|
| [[功能包/simple_follower]] | 巡线、激光、视觉、AR 跟随 | 图像、`/scan`、目标位置 | `/cmd_vel` |
| `kcf_track` | 用户框选目标后的 KCF 跟踪 | RGB 图像 | 目标框/位置 |
| `rrt_exploration` | 搜索未知地图边界并派发目标 | `/map`、TF、边界点 | 导航目标 |
| `wheeltec_multi` | 主车轨迹到从车期望位置 | 多机 TF/位姿、雷达 | 从车速度 |

## simple_follower 的分层

视觉和激光跟随通常拆成两个节点：Tracker 负责检测目标，Follower 负责把目标位置转换成速度。巡线还同时启动雷达避障节点。因此阅读时不要只看发布 `/cmd_vel` 的脚本，还要追踪中间自定义 `position.msg`。

```bash
roslaunch simple_follower line_follower.launch
roslaunch simple_follower laser_follower.launch
roslaunch simple_follower visual_follower.launch
roslaunch simple_follower ar_follower.launch
```

重点源码：`line_follow.py`、`laserTracker.py`、`laser_follow.py`、`visualTracker.py`、`visual_follow.py`、`ar_follow.py`、`avoidance.cpp`。

## 控制逻辑

常见控制量是横向误差、角度误差和距离误差。最简单的比例控制为：

$$v=k_d(d-d^*),\quad \omega=k_a e_{angle}$$

实现中还应加入死区、最大速度、加速度限制、目标丢失超时和紧急停车距离。检测频率低时，控制频率再高也无法消除明显延迟。

## 自主探索

`rrt_exploration` 查找已知自由空间和未知空间的交界（frontier），选取候选目标交给 Navigation Stack。它依赖的不是单个节点，而是完整的 SLAM、TF、地图、定位/导航与探索边界配置。

```bash
roslaunch turn_on_wheeltec_robot rrt_slam.launch
```

在 RViz 中需要设置探索区域边界和起点，并观察 `frontiers`、`centroids`、全局树与局部树等可视化话题。

## 多机编队

`wheeltec_slave.launch` 同时启动底盘、雷达、地图、AMCL、主从 TF 监听和避障。`slave_x/slave_y` 表示从车相对主车的期望位置。多机系统最容易出错的是命名空间、同名 TF、共享 ROS Master 和机器时间不同步。

## 推荐实验

- [ ] 记录目标误差与 `/cmd_vel`，画出控制响应。
- [ ] 遮挡目标，确认超时后停车。
- [ ] 调整跟随距离与最大速度。
- [ ] 在雷达跟随前方放置第二个物体，观察目标选择。
- [ ] 检查是否同时存在多个 `/cmd_vel` 发布者。

## 安全注意

第一次真机运行应架空驱动轮或设置低速度；任何感知节点崩溃、消息停止或目标丢失时，都应有明确的零速度策略。仅依靠节点退出并不能保证底盘立即停止。
