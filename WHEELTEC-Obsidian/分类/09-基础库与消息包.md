# 基础库与消息包

基础包通常没有面向用户的独立启动命令，却决定了其他包如何编译、交换数据和加载插件。学习原则是“从使用者反查定义”，不必逐行阅读所有底层实现。

## 消息、服务与动作

ROS1 接口有三种主要形式：

- Topic：连续数据流，例如激光、图像、里程计。
- Service：短请求/响应，例如设置麦克风或保存状态。
- Action：耗时、可反馈、可取消的任务，例如导航目标和机械臂轨迹。

本仓库的自定义接口包括：

| 包 | 接口 |
|---|---|
| `simple_follower` | `position.msg`，传递目标位置 |
| `wheeltec_yolo_action` | `position.msg`、`CtrlData.msg` |
| `bodyreader` | body、joint、posture、mask 等人体消息 |
| `xf_mic_asr_offline` | PCM/position 消息及多种麦克风配置 service |
| `lslidar_msgs`、`lslidar_x10_msgs` | 镭神雷达驱动消息 |
| `world_canvas_msgs` | APP/地图保存相关消息与节点 |

查看接口：

```bash
rosmsg show simple_follower/position
rossrv show xf_mic_asr_offline/Start_Record_srv
rostopic type /某话题
rosmsg show $(rostopic type /某话题)
```

## Navigation 基础组件

`nav_core` 定义全局规划器、局部规划器和恢复行为的 C++ 插件接口。`move_base` 通过 pluginlib 动态加载 `navfn`、`global_planner`、DWA、TEB 等实现。因此学习 Navigation 源码时应先理解接口，再看某一个插件。

`voxel_grid` 提供三维体素占用表示，供代价地图处理带高度的障碍；`costmap_2d` 再把信息组织成导航可用的二维代价层。

## SLAM 与驱动依赖

- `open_karto`：Karto 的扫描匹配和图结构核心。
- `sparse_bundle_adjustment`：Karto 图优化使用的稀疏优化组件。
- `ddynamic_reconfigure`：RealSense 使用的运行时动态参数机制。
- 雷达 msgs 包：隔离厂商协议数据与标准 ROS 消息。

## package.xml 与 CMakeLists.txt

阅读基础包时同时关注：

1. `package.xml` 的 build/exec 依赖。
2. `CMakeLists.txt` 的 `add_message_files`、`add_service_files`。
3. `generate_messages` 使用的标准消息依赖。
4. `catkin_package` 导出的 include、library 和依赖。
5. 插件描述 XML 与 `PLUGINLIB_EXPORT_CLASS`。

## 何时需要深入源码

只有出现以下情况才优先深入基础库：消息定义不满足需求、插件加载失败、算法需要自定义接口、序列化兼容问题、或底层性能成为瓶颈。普通应用开发通常只需掌握接口和参数。

## 推荐实验

- [ ] 新建一个 `.msg`，完成生成并用 Python/C++ 发布订阅。
- [ ] 用 `rosmsg show` 追踪嵌套消息结构。
- [ ] 找到 `move_base` 加载全局规划器的插件配置。
- [ ] 比较标准 `sensor_msgs/LaserScan` 与厂商自定义雷达消息。
- [ ] 修改消息后理解为什么必须重新编译并重新 source 工作空间。

## 常见问题

- 找不到消息：未编译、未 source、依赖声明缺失。
- MD5 不一致：不同机器使用了不同版本的消息定义。
- 插件加载失败：类名、库名、导出宏或插件 XML 不一致。
- 运行有包但编译找不到：工作空间 overlay 顺序或 `CMAKE_PREFIX_PATH` 错误。
