# AUBO 分拣控制节点（aubo_sorting_core）技术文档

> 版本：0.1.0（对应本仓库 `aubo/aubo_sorting_core`）
> 适用平台：ROS 1（catkin）+ MoveIt；固定平台与移动底盘通用
> 本文档基于源码逐文件梳理，可作为分拣控制节点的设计说明与维护参考。

---

## 1. 包概述与定位

`aubo_sorting_core` 是 AUBO 机械臂的**平台无关分拣执行层**，只维护一份基于 MoveIt 的
抓取-分拣状态机。它与场景层的职责边界为：

| 层 | 包 | 职责 |
| --- | --- | --- |
| 场景层 | `aubo_sorting`（固定底座）/ `aubo_mobile_sorting`（移动底盘） | 启动编排、检测器选择、YAML 参数（桌位、放置点、姿态、速度等） |
| 执行层 | `aubo_sorting_core`（本包） | 状态机、感知目标跟踪、实例队列调度、MoveIt 规划执行、夹爪控制、工作区/OctoMap 管理 |

**关键约定：**
- 核心不执行图像识别，也不做底盘导航；检测消息与类别参数由上层提供。
- 支持颜色分拣与 YOLO 类别分拣（`DetectedObject.color/class_name` 统一作为类别键）。
- 提供 C++（默认 `color_sorting_task_cpp`）与 Python（`scripts/color_sorting_task.py`，回退/对照用）双实现；`continuous_sorting: true` 时 Python 入口也转交 C++ 执行器。
- 所有 C++ 源文件编译为 `color_sorting_task` 库，由**一个任务对象**共享状态与锁，不是独立节点。
- 从场景 launch 启动，不要直接运行核心脚本。

## 3. 系统架构与线程模型

### 3.1 线程结构

| 线程 | 来源 | 职责 |
| --- | --- | --- |
| 主线程 | `main()` | 初始化 ROS、创建任务对象、`start()`、`waitForShutdown()` |
| ROS 回调线程 ×4 | `ros::AsyncSpinner(4)` | `detectionCallback`、`graspStatusCallback`、`cloudCallback`、`planningSceneCallback`、`workspaceUpdateCallback` |
| 初始化线程 | `initialization_thread_` | 校验 SRDF named target、机械臂极限、等待夹爪/吸附插件、加桌面碰撞、刷 OctoMap |
| 任务执行线程 | `operation_thread_` | 串行执行一次 operation（观察/准备/分拣/回零/开爪）；通过 `operation_mutex_` 保证同一时刻仅一个操作 |
| 目标队列线程 | `target_thread_`（连续模式） | 消费最新检测帧，更新实例队列，发布 `/sorting/target_cache`；不执行 MoveIt |

**并发安全要点：**
- 感知回调只投递**最新一帧**（`pending_detection_` 只保留时间戳最新者），队列不积压图像。
- 机械臂运动期间**不持有队列锁**；领取目标时复制完整抓取信息（执行坐标冻结），后续帧不影响在途轨迹。
- `data_mutex_` 保护状态/检测/夹爪状态等共享数据；TF 查询在锁外执行，避免等待变换阻塞回调。
- 停止语义：`stop_requested_` 原子标志 + `arm_->stop()` + 夹爪 goal 取消/Inspire `set_es`；所有等待均通过 `wallSleep` 每 20 ms 检查退出条件（Gazebo 暂停 `/clock` 时仍可响应停止）。

### 3.2 启动流程（initialize）

1. 校验配置的 named target（`work_ready` / `observe` / `down` 等）确实存在于加载的 SRDF 规划组；
2. 校验 `upperArm_joint` 的 URDF 与 MoveIt 极限均为 ±60°（±1.047198 rad），防止旧模型驱动翻腕；
3. 等待 Gazebo 抓取吸附插件（`ready`/`detached:` 状态）就绪；
4. 等待夹爪后端（trajectory Action 或 Inspire 服务）就绪；
5. 向规划场景添加桌面碰撞体（`sorting_table`，ADD 替换语义）；
6. 如启用 `require_octomap`，等待新鲜点云 → 调 `/clear_octomap` → 等待新 OctoMap 序列；
7. 置 `initialized_=true`，发布 `IDLE`；按 `auto_move_to_observation` / `auto_start` 决定是否自动进入观察/分拣。

初始化任何一步失败即进入 `ERROR` 并发布 `CONFIGURATION_FAILED` 类失败。

## 4. ROS 接口规范

### 4.1 订阅（输入）

| 话题 | 类型 | 用途 |
| --- | --- | --- |
| `/sorting/detections` | `aubo_perception/DetectedObjectArray` | 感知检测结果（见 4.4） |
| `/sorting/grasp/status`（可配） | `std_msgs/String` | Gazebo 吸附插件状态：`ready` / `attached:<model>` / `detached:<model>` / `error:` |
| 点云话题（可配，默认 `/workspace_camera/depth/color/points`） | `sensor_msgs/PointCloud2` | 仅 `require_octomap` 时订阅，用于确认新鲜点云 |
| `/move_group/monitored_planning_scene`（可配） | `moveit_msgs/PlanningScene` | 仅 `require_octomap` 时订阅，跟踪 OctoMap 序列号 |
| `/sorting/workspace_update`（可配） | `std_msgs/String` | 工作区 JSON 动态下发（换桌/换放置点/换模型名） |

### 4.2 发布（输出）

| 话题 | 类型 | 说明 |
| --- | --- | --- |
| `/sorting/state` | `std_msgs/String` | 状态机输出（latched），格式 `状态 | 详情` |
| `/sorting/detection_summary` | `std_msgs/String` | 每帧各类别计数，如 `red:2  green:0  blue:1` |
| `/sorting/base_locked`（可配） | `std_msgs/Bool` | 机械臂执行期间锁底盘（移动平台用） |
| `/sorting/failure`（可配） | `std_msgs/String` | 失败原因，格式 `类别 | 详情`；无失败时发布空串 |
| `/sorting/target_cache` | `std_msgs/String` | 目标/实例队列 JSON（连续模式 `schema_version:2`，键为实例 ID） |
| `/sorting/grasp/attach` | `std_msgs/String` | 请求 Gazebo 吸附指定模型 |
| `/sorting/grasp/detach` | `std_msgs/String` | 请求 Gazebo 释放模型 |

失败类别常量：`PLANNING_FAILED`（无法生成非空 MoveIt 轨迹）、`EXECUTION_FAILED`（执行失败）、
`DETECTION_FAILED`（感知超时/几何无效/预留失效）、`GRIPPER_FAILED`、`CONFIGURATION_FAILED`。
执行器失败不会混为规划失败。

### 4.3 服务（外部控制，`std_srvs/Trigger`）

| 服务 | 行为 |
| --- | --- |
| `/sorting/move_to_observation` | 移动到观察位姿并确认检测（连续模式同时重置实例队列） |
| `/sorting/start` | 开始分拣；前置条件 `observation_ready_`（已确认观察） |
| `/sorting/stop` | 请求停止：置停止标志、取消夹爪/机械臂运动；空闲时也发布新 `STOPPED` + `base_locked=false` 供导航编排确认 |
| `/sorting/open_gripper` | 张开夹爪并释放当前吸附模型 |
| `/sorting/prepare_work` | 移动底盘到达工位后编排用：刷 OctoMap + 加桌面碰撞 + 移动至 `work_ready` |
| `/sorting/home` | 回到 `finish_named_target`（如 `down`） |
| `/sorting/configure_workspace` | 空闲时从参数服务器 `/sorting/workspace_config` 或话题缓存读取工作区并应用；切换桌会清空目标 |

### 4.4 输入消息定义

`aubo_perception/DetectedObjectArray.msg`：

```
std_msgs/Header header
aubo_perception/DetectedObject[] objects
bool observation_valid        # false 表示几何不可用/不完整，绝不作为"桌面为空"的证据
string sensor_frame           # header.stamp 时刻的光学坐标系，用于排除夹爪的桌面投影
```

`aubo_perception/DetectedObject.msg` 关键字段：

| 字段 | 说明 |
| --- | --- |
| `color` / `class_name` | 类别键（颜色或 YOLO 类别，二者统一作为分拣类别） |
| `pose` | 物体中心位姿（`header.frame_id` 下） |
| `contour_area` / `confidence` | 轮廓面积 / 模型置信度 |
| `grasp_width` / `grasp_angle` / `grasp_geometry_valid` | 短边宽度/角度（XY 平面）及有效性 |
| `depth_valid` / `object_height` | 深度高度是否经过桌面+物高校验 / 物高 |

**兼容性注意**：该消息含 `observation_valid` 与 `sensor_frame`，ROS 消息 MD5 变化，感知、分拣、Gazebo 插件等所有使用方必须一起重编译；自定义感知节点必须正确置位（默认 false 不会触发抓取或完成判定）。

### 4.5 Action / 服务客户端

- **MoveIt**：`moveit::planning_interface::MoveGroupInterface`（规划组 `aubo_i5`，默认 10 次规划尝试，规划时间 `planning_time`）。
- **夹爪（trajectory 后端）**：`control_msgs/FollowJointTrajectoryAction`，轨迹含当前关节位置+目标点、两端零速、默认 0.8 s。
- **夹爪（inspire 后端，仅 C++）**：`/inspire_gripper/move_max`、`move_min`、`get_state`、`set_es`；张开等待状态 1，闭合等待状态 2/6，超时/异常调用停止服务。
- **OctoMap**：`/clear_octomap`（`std_srvs/Empty`，仅 `require_octomap`）。

## 5. 任务状态机

状态枚举（`enum class State`，对外发布保持字符串协议，导航任务与 RViz 面板无需迁移）：

`INITIALIZING → IDLE → OBSERVING / PREPARING / OPENING / HOMING → READY → SORTING（内部 DETECTING ⇄ PICKING）`

以及终止态 `STOPPED`、`ERROR`。

```
                ┌─────────── 初始化失败/配置错误 ───────────┐
                ▼                                         │
        ┌─ INITIALIZING ─┐  成功   ┌─── IDLE ───┐          │
        └────────────────┘ ──────► │（空闲就绪） │          │
                                   └──┬──┬──┬──┬┘          │
      /sorting/move_to_observation    │  │  │  │           │
                                   OBSERVING │ │           │
                                      │成功 │ │            │
                                      ▼    │ │            │
                                    READY  │ │            │
                                      │    │ │            │
        /sorting/start                 │    │ │            │
                                      ▼    │ │            │
                                   SORTING  │ │            │
                              DETECTING⇄PICKING            │
                                  │完成  │  │              │
                                  ▼      │  │              │
                       HOMING（finish 位）│  │              │
                                  │      │  │              │
                                  ▼      │  │              │
                                READY    │  │              │
      /sorting/stop ──► STOPPED ◄────────┴──┴──────────────┘
      任意操作失败 ──► ERROR
```

流转要点：
- `startOperation(state, operation)` 是统一执行框架：`busy_` 互斥 → 锁底盘 → 清失败 → 起线程执行 → 解锁底盘；成功发布 `READY | waiting for panel command`，失败 `ERROR | operation failed`，被停止 `STOPPED | operation cancelled`。
- `SORTING` 连续模式内部状态：`DETECTING`（构建/确认实例队列）⇄ `PICKING`（抓取单个实例），全部完成或空场景确认后回 `HOMING` 或直接成功。
- `/sorting/start` 仅当 `observation_ready_=true`（观察位已确认检测）时接受。

## 6. 核心模块详解

### 6.1 参数加载与校验（task_parameters.cpp）

- 默认值见第 8 节参数表；`place_targets` 为必需参数，缺失直接抛异常。
- 校验规则（违反即启动失败）：
  - 队列距离参数必须满足 `duplicate < stable < reserved < match`；
  - `queue_retention ≥ queue_max_age`、`queue_reserved_max_age ≥ queue_max_age`、`queue_empty_min_frames ≥ 2`、`queue_empty_confirmation < detection_timeout`；
  - 抬升参数有限正数，`lift_min_height ≤ lift_height` 且必须高于抓取 TCP 的桌面相对高度；
  - `use_detected_width` 要求 trajectory 后端及已标定开口端点/系数；
  - `pregrasp_wrist1_limit ∈ [0, 3.04]` rad。
- `verifyLoadedUpperArmLimit()`：读取 `/robot_description` 的 URDF 与 `/robot_description_planning/joint_limits/upperArm_joint/*`，两者必须均为 ±60°，防止陈旧模型。

### 6.2 目标跟踪与实例队列（target_tracking.cpp / instance_tracking.cpp / instance_queue.hpp）

#### 旧模式（`continuous_sorting: false`）
- 每类只保留**轮廓面积最大**的候选，转换到 `target_cache_frame`；
- 多帧确认：Welford 在线均值/离散度统计（不保存全部历史帧），`count ≥ target_cache_min_observations` 才可用；
- 检测超时后按 `target_cache_fallback_delay` 启用缓存兜底（`cachedObject`），年龄/观测数校验后才可用；
- `waitForObject`：新鲜检测优先，累积 `detection_samples` 帧后取平均位置，同类多目标间隔 >0.03 m 时清空重采，避免把相隔较远的目标平均到中间。

#### 连续模式（默认 `continuous_sorting: true`）
- **投递策略**：检测回调只保留最新一帧给 `target_thread_`；队列不积压图像，运动期间不持有队列锁。
- **实例队列**（`InstanceQueue<Payload>`，纯 C++、不依赖 ROS）：
  - 状态：`candidate`（等待多帧确认）→ `ready`（可分配）→ `reserved`（已领取执行中）→ `done`（完成，短暂屏蔽残留画面）/ `review`（执行失败，需重新确认）；
  - 关联规则：同类 + XY 距离 ≤ `queue_match_distance` 一对一匹配（按距离近到远选边，每帧每观测/轨迹最多匹配一次）；≤ `stable_distance` 且间隔 ≤ `confirmation_gap` 才累计确认帧并做坐标平滑（0.5 加权）；
  - 同帧同色且距离 < `queue_duplicate_distance` 视为重复检测，只计一次；
  - 队列容量 200，超龄未预留轨迹在新帧到达时清理；实例 ID 在节点生命周期内不复用；
  - 领取（`reserve`）：按 `sort_colors` 优先级、同色按 ID 序，返回独立执行快照（坐标冻结）。
- **执行前复核**（`validateReservedTarget`）：下降前检查目标仍为 `reserved`、无位移证据（`disturbed`）、最后观测 ≤ `queue_reserved_max_age`（默认 30 s，宽限手眼相机被夹爪遮挡）、检测流新鲜度 ≤ `queue_frame_max_age`（默认 1 s）。
- **空场景确认**：观察位收到 ≥ `queue_empty_min_frames` 帧有效空检测、持续 ≥ `queue_empty_confirmation` 秒且检测仍新鲜才判定桌面已清空；感知失联、无效深度、无效 TF、不满足抓取几何的物体都不能作为空证据。
- **排除区**：抓取区域为 `table_frame` 下桌面 XY 边界内，排除所有类别放置点周围 `queue_place_exclusion_radius`（0.08 m）；**夹紧后**才排除 TCP 邻域及其沿相机射线投影到桌面的邻域（`queue_gripper_exclusion_radius` 0.10 m），防止手中物体重新入队，同时保证预抓取运动期间仍能确认预留目标。
- **遮挡与跳变**：预留目标短暂遮挡保留；超出关联半径的同色新观测会使旧就绪目标取消（防旧坐标残留）；匹配只依据几何，不保证交叉/重叠物体的身份。
- 连续模式 `/sorting/target_cache` 输出 `schema_version:2`，`targets` 键为实例 ID，含 `id/color/status/position/observations/confidence/age/picked`；`confidence` 是稳定确认进度，不是模型概率。

### 6.3 工作区与场景管理（workspace_manager.cpp）

- **工作区配置**双通道：参数服务器 `/sorting/workspace_config`（优先，非法直接报错）或 `/sorting/workspace_update` 话题 JSON（节点空闲时缓存为 pending）；`/sorting/configure_workspace` 应用。
- `WorkspaceConfig`：`id`、`table_center/size`、`table_frame`、`table_z`、`place_frame`、`place_targets`（每类别 1 个 [x,y]）、`grasp_model_names`。
- 应用工作区：持 `queue_mutex_` 替换坐标帧/ROI/放置点 → 用同一 `sorting_table` ID **ADD 替换**桌面碰撞体（不清理其他节点障碍物）→ 清空目标缓存与队列 → 重置观察就绪。
- **桌面碰撞体**：`table_frame` 下盒体（尺寸 + 2×`table_collision_margin`），转换到规划帧后 `applyCollisionObject(ADD)`，并设为 MoveIt 支撑面。
- **OctoMap 刷新**（`refreshOctomap`）：等新鲜非空点云 → 调 `/clear_octomap` → 等规划场景 OctoMap 序列号递增；每次抓取前与观察前均刷新，开始/重观察/切工作区会重建缓存，不沿用上次停靠坐标。

### 6.4 运动执行（motion_executor.cpp）

- `planAndExecute`：`setStartStateToCurrentState` → MoveIt 规划 → 非空轨迹校验 → 执行；失败按 `PLANNING_FAILED` / `EXECUTION_FAILED` 分类上报。
- **预抓取 wrist1 限制**（`pregrasp_wrist1_limit`，固定平台 1.2 rad）：仅预抓取阶段对 `wrist1_joint` 施加相对零位的路径约束并逐点复核，排除同位姿约 ±2.8 rad 的翻腕逆解；抓取下降、放置、观察、回收不沿用。限制必须包含起始姿态（observe 的 wrist1≈-0.91 rad）。
- `cartesianTo`：`computeCartesianPath`（步长 `cartesian_step`）→ 比例不足且 `require_octomap` 时刷新 OctoMap 重试一次 → `IterativeParabolicTimeParameterization` 时间参数化（速度/加速度缩放）→ 执行；比例 < `minimum_cartesian_fraction` 时回退关节空间规划；**抬升要求 100% 笛卡尔路径**，部分路径不执行。
- `liftWithRecovery`（抓取后抬升的有界高度重试）：候选高度序列由 `liftHeightCandidates(lift_height, lift_min_height, lift_height_step, lift_max_attempts)` 生成（默认 0.30 → 0.28 → …），**只在抬升规划失败时降低目标**，不重试控制器执行失败/停止；每次重新规划并检查碰撞；失败保留抓取吸附，最终失败沿用失败清理。导航分拣示例：0.26→0.24→0.22→0.20→0.18 m。
- `moveNamed`：校验目标在 SRDF 中存在、当前关节值容差 1e-3 内则跳过，否则规划执行。
- `commandGripper`：trajectory 后端发送含起止点的关节轨迹（默认 0.8 s，路径容差 0.10、目标容差 0.03）；inspire 后端调用服务并轮询 `motion_state`，超时调用 `set_es` 停止并报 `GRIPPER_FAILED`。

### 6.5 抓取吸附（grasp_attachment.cpp，Gazebo 专用）

- 话题协议：`/sorting/grasp/attach|detach` 发模型名；`/sorting/grasp/status` 回 `attached:<model>` / `detached:<model>` / `error:`。
- 通过**状态序列号递增 + 状态匹配**确认成功；`nearest:<名称>` 模式下接受 `attached:<名称>` 或 `<名称>_<后缀>`（插件选择夹爪附近实例，保留距离与横向对中检查）。
- 吸附命令发出即记录 `attached_model_` 所有权；仅 pick/place 失败才清理其持有的吸附，观察/检测/准备/回零失败不触发释放；真机不用吸附，规划失败不自动张爪。
- `releaseAttachedObjectNoWait`：析构/异常路径用的"发即走"释放。

### 6.6 单目标抓放（pick_place.cpp）

`pickAndPlace(detected)` 完整动作序列：

1. 校验抓取几何（有限坐标、物高、depth 模式高度容差、检测角度/宽度有效性）；
2. 若启用 `use_detected_width`，按米制窄边×闭合系数换算夹爪闭合位置（需已标定开口端点）；
3. 计算抓取高度 `grasp_z = 中心高 + grasp_height_offset`（须在桌面上方且低于接近/抬升高度）；
4. 执行前复核预留目标（`validateReservedTarget`）→ 张开夹爪 → 预抓取位（`pregrasp_height`，带 wrist1 约束）→ 再复核 → 笛卡尔直线下降到抓取位；
5. Gazebo 吸附（连续模式 `nearest:<模型名>`，按颜色映射 `grasp_model_names`，缺省 `颜色_block`）；
6. 闭合夹爪（失败则释放吸附）→ 置 `grasp_secured_=true`（此后才屏蔽夹爪邻域检测）→ 等待 0.5 s → 有界高度抬升；
7. 放置点转换到目标坐标系 → 预放置位（`preplace_height`）→ 笛卡尔下降到放置位 → 张开夹爪 → 释放吸附 → 等待 0.5 s → 笛卡尔退离至预放置位。

`sortingOperation`（旧模式整轮）：遍历 `sort_colors`，跳过已完成颜色，`waitForObject` → `pickAndPlace` → 标记完成；每抓完一个颜色回观察位再抓下一个；全部完成回 `finish_named_target`。

## 7. 连续分拣主循环（continuousSortingOperation）

```
resetInstanceQueue() → DETECTING
循环（20 Hz，直到 stop）：
  1) 检测流新鲜（≤ queue_frame_max_age）时尝试 reserve()：
     领取成功 → PICKING <color> #<id>
       → 冻结执行快照（active_instance_id_）
       → refreshOctomap + addTableCollision
       → pickAndPlace
       → finish(id, success)：成功→done(屏蔽期)，失败→review+invalidate()
       → 若成功：更新队列纪元（丢弃释放前旧帧）→ 回到 DETECTING，设 2 s 宽限
       → 若失败：退出（由停止/恢复流程处理不确定的夹持状态）
  2) 空场景确认条件满足 → HOMING(finish) 或直接成功
  3) 超时（detection_timeout）：
     已观察过 → DETECTION_FAILED 失败退出
     未观察 → 回观察位重新确认，invalidate 队列，重建采样周期
```

设计要点：
- 抓放完成后**不强制回观察位**：等待一帧释放后的有效检测，再领取仍有效的实例。
- 队列短暂不可用时等待 `target_cache_fallback_delay`（2 s），随后回观察位重新确认。
- 每次抓取保留 OctoMap 与桌面碰撞体更新；底盘锁由操作框架维持。
- 执行失败/急停退出当前操作，待人工复核后重新观察和开始，**不自动在夹持状态不明时抓下一个**；`done` 仅表示动作成功，无夹持反馈时不声称视觉确认抓取成功。

## 10. 启动与部署

- 从场景 launch 启动（示例：`roslaunch aubo_sorting color_sorting.launch`），核心包不单独启动；
- 默认执行器 `task_executable:=color_sorting_task_cpp`；`continuous_sorting: false` 时才可能运行旧 Python 流程；
- 观察姿态必须在部署时确认覆盖需要处理的桌面区域；有效空检测依赖相机覆盖抓取区，不能证明视野外区域为空；
- 若 YOLO 推理超过 1 s，需按实测延迟设置 `queue_frame_max_age`，不能通过重写图像时间戳规避过期检查。
