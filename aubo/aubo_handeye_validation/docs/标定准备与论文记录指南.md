# 固定相机手眼标定：上位机规划与论文记录

本指南适用于固定 D435i、AUBO i5 和当前实机工位。运动由 RViz 的 MoveIt Plan/Execute 完成，标定界面仅负责采样、求解和保存。以下命令供操作者现场执行；本次准备工作没有启动设备或发送运动命令。

## 1. 固定实验条件

- 相机与机械臂基座相对固定；移动底盘（如有）保持静止。拍摄一张完整工位照片和一张末端标记安装近照。
- 将 ArUco 标记贴到平整刚性板，再刚性固定在末端，不能只靠手拿或松软纸片。记录标记字典、ID、实际黑色正方形边长；边长不含外围白边。当前示例 ID=30、边长 100 mm，仅在实际标记一致时使用。
- 本轮统一使用 640×480 彩色图像。标记应清晰、曝光不过饱和，停稳后再采样，避免上次样本中的运动模糊。
- 明确四个坐标系：`base_link`、`gripper_link`、`camera_color_optical_frame`、`aruco_marker_frame`。输出为 `base_link -> camera_color_optical_frame`，列向量约定 `p_base = R * p_camera + t`。
- 本轮先沿用驱动发布的内参，保存实际 `/camera/color/camera_info`。上次自标定 YAML 并未接入检测器，不能把它直接写成本次外参实验实际使用的内参。若以后换内参，应作为另一轮实验单独记录，并重新进行外参求解与验证。
- 原有旧外参保留为基线，使用新的 namespace 保存本轮结果，避免覆盖旧文件。

## 2. 环境与本轮数据目录

每个终端加载 ROS 和工作区：

```bash
cd /home/zlab/aubo/ros_mobile_manipulation_lab
source /opt/ros/noetic/setup.bash
source devel/setup.bash
```

在专门用于记录数据的终端创建目录：

```bash
export HANDEYE_RUN_DIR="$PWD/records/handeye_$(date +%Y%m%d_%H%M%S)"
mkdir -p "$HANDEYE_RUN_DIR/baseline" "$HANDEYE_RUN_DIR/fit" "$HANDEYE_RUN_DIR/photos"
cp src/aubo/aubo_ros_control/config/aubo_realsense_handeye_eye_on_base.yaml "$HANDEYE_RUN_DIR/baseline/old_extrinsics.yaml"
cp src/aubo/aubo_handeye_validation/docs/templates/handeye_experiment_template.yaml "$HANDEYE_RUN_DIR/experiment.yaml"
cp src/aubo/aubo_handeye_validation/docs/templates/handeye_pose_log.csv "$HANDEYE_RUN_DIR/pose_log.csv"
```

`HANDEYE_RUN_DIR` 是当前终端变量，其他终端需要使用本轮同一个绝对路径；不要分别生成新的时间戳。填写 `experiment.yaml` 中待确认项。

先保存上一轮仍在内存中的样本，再关闭上一轮标定、分拣或示教器接管程序；不要同时启动两套机械臂驱动或相机驱动。

## 3. 启动上位机规划环境

对于当前桌面、支架与容器安装，复用工位入口加载真实机械臂和碰撞场景，只开启规划环境：

```bash
PYTHONNOUSERSITE=1 roslaunch aubo_sorting eye_to_hand_can_sorting_real.launch \
  robot_ip:=192.168.1.2 \
  start_camera:=false start_gripper:=false \
  start_perception:=false start_task:=false rqt:=false
```

该组合使用眼在手外模型 `aubo_i5.xacro`，不启动分拣循环或旧相机外参发布器。现场核对碰撞场景与实物一致，并将标定板及新增支架的实际突出包络纳入场景。若已经有相同配置的真实机械臂和 MoveIt 会话，复用现有会话即可。

在 RViz 中选择规划组 `aubo_i5`，将速度、加速度缩放先设为 `0.05`。先 Plan 检查完整轨迹，再 Execute；首次执行确认真实机械臂与 RViz 的反馈一致、标记持续可见。启动程序本身不会自动采集一套标定姿态。

## 4. 启动相机、ArUco 和采样界面

新终端：

```bash
PYTHONNOUSERSITE=1 roslaunch easy_handeye aubo_realsense_calibration.launch \
  namespace_prefix:=aubo_handeye_new \
  eye_on_hand:=false \
  robot_base_frame:=base_link \
  robot_effector_frame:=gripper_link \
  tracking_base_frame:=camera_color_optical_frame \
  marker_id:=30 marker_size:=0.1 \
  width:=640 height:=480 fps:=30
```

`marker_size:=0.1` 必须改成实际测得的米制边长；ID 和字典也必须对应。标记字典的选择应与 aruco_ros 检测器配置一致，不能只确认编号。复用已运行的同名相机时，增加 `start_camera:=false`，并检查其分辨率和图像话题。

此入口保留 `freehand_robot_movement=true`，表示由外部 RViz 控制运动；它不等于必须使用示教器。标定全过程不要启动 `aubo_realsense_publish_only.launch` 或 `eye_to_hand_camera_real.launch` 发布旧外参。

查看识别图像：

```bash
PYTHONNOUSERSITE=1 /usr/bin/python3 \
  /opt/ros/noetic/lib/rqt_image_view/rqt_image_view /aruco_tracker/result
```

检查两条采样链：

```bash
rosrun tf tf_echo base_link gripper_link
rosrun tf tf_echo camera_color_optical_frame aruco_marker_frame
```

采样时两条链分别来自真实关节反馈与视觉检测。无需提前让相机和基座通过旧标定相连。

## 5. 记录实际内参并采集拟合姿态

在数据记录终端执行：

```bash
rostopic echo -n 1 /camera/color/camera_info > "$HANDEYE_RUN_DIR/camera_info_used.yaml"
rosparam dump "$HANDEYE_RUN_DIR/aruco_params.yaml" /aruco_tracker
rosparam dump "$HANDEYE_RUN_DIR/fit/parameters.yaml" /aubo_handeye_new_eye_on_base
PYTHONNOUSERSITE=1 /usr/bin/python3 -c 'import cv2; print(cv2.__version__, cv2.__file__)' > "$HANDEYE_RUN_DIR/opencv.txt"
rosbag record --lz4 -O "$HANDEYE_RUN_DIR/raw.bag" \
  /tf /tf_static /joint_states /aubo_i5/joint_states \
  /camera/color/image_raw /camera/color/camera_info \
  /aruco_tracker/transform /aruco_tracker/pose /aruco_tracker/result
```

记录 bag 的终端会持续运行，采集与备份命令在另一个加载相同 `HANDEYE_RUN_DIR` 的终端执行。图像会占磁盘空间，采集前检查可用空间；结束时 Ctrl+C 正常关闭 bag。

建议采集 25–30 个不同的拟合姿态（是本轮采集目标，不是已完成数量）：覆盖工作区中心与四周、至少三个可行高度，围绕至少两个非平行轴改变朝向，并包含适度复合旋转。可从相对中间姿态约 ±15° 至 ±25° 的小范围变化开始，具体受可达性、视野和碰撞约束限制。不要只平移或只绕一个轴旋转。

每个姿态按同一流程操作：

1. RViz Plan，检查完整路径，再 Execute。
2. 到位后等待约 1–2 秒，确认机械臂及标记停止运动，识别框、坐标轴稳定。
3. 在 easy_handeye 中点击 Take Sample；在 `pose_log.csv` 记录姿态编号、阶段、时间、观察与剔除原因。
4. 如果模糊、遮挡、位姿跳变或相机/标记松动，保留原始记录并说明原因；不要无记录地删除异常样本。

随时备份当前样本，尤其是在 Compute 或关闭程序之前：

```bash
rosservice call /aubo_handeye_new_eye_on_base/get_sample_list '{}' \
  > "$HANDEYE_RUN_DIR/fit/samples_latest.yaml"
```

完成采集后点击 Compute，再 Save。可分别保存 Horaud、Park 等算法的候选，记录算法名及对应输出；不要把切换算法当作补救采样质量的方法。当前环境缺少接口的问题已在服务启动环境中修复。

本轮命名空间默认保存到 `~/.ros/easy_handeye/aubo_handeye_new_eye_on_base.yaml`。例如先选择 Horaud 并保存，再复制到本轮目录：

```bash
cp "$HOME/.ros/easy_handeye/aubo_handeye_new_eye_on_base.yaml" \
  "$HANDEYE_RUN_DIR/fit/extrinsics_horaud.yaml"
```

更换算法前先复制上一候选，避免同一 namespace 的保存操作覆盖它。保存算法名、样本数与剔除记录。

## 6. 留出姿态验证

相机、标记、机械臂基座的安装保持不变，继续运行机器人反馈与 ArUco 检测。额外规划 15–20 个未加入拟合样本列表的姿态；它们不再点击 Take Sample，而由独立验证节点采集。

启动验证器，输出子目录必须尚不存在：

```bash
PYTHONNOUSERSITE=1 roslaunch aubo_handeye_validation validate_handeye.launch \
  calibration_file:="$HANDEYE_RUN_DIR/fit/extrinsics_horaud.yaml" \
  output_dir:="$HANDEYE_RUN_DIR/validation_horaud"
```

每到一个新的验证姿态，停稳后执行：

```bash
rosservice call /handeye_validation/capture '{}'
```

每次默认采集 2 秒、至少 10 个不同时间戳观测；移动或时间戳不合要求时采集会拒收。完成后：

```bash
rosservice call /handeye_validation/report '{}'
```

输出包括 `session.json`（原始观测和候选外参）、`report.json`（汇总统计）、`poses.csv`（逐姿态数据）。比较旧外参、不同算法时应使用同一批原始验证观测离线重算，避免换一批姿态造成不公平比较；保存原始 session，不覆盖它。

算法选择与最终报告使用的数据也应区分：若用这批姿态挑选算法或调参数，它就是选择集。最终性能主张再用一批未参与选择的新姿态验证，或者明确说明报告的是选择集结果，不能称为独立测试。

一致性指标不等于绝对精度。若论文需要宣称绝对定位误差，应增加独立测量的参考点/标记安装位姿并报告测量方法；抓取实验则另记成功次数、总次数、目标类别、位置分布和失败原因。

## 7. 论文参数与文件对应关系

| 类别 | 必须记录的内容 | 原始依据 |
|---|---|---|
| 实验设备与条件 | 相机型号/序列号、分辨率/帧率、机器人型号、安装形式、工位与标记照片 | experiment.yaml、photos、实际设备信息 |
| 实际使用的内参 | K、D、畸变模型、原始/校正图像状态、光学 frame | camera_info_used.yaml、aruco_params.yaml |
| 标记与采样 | 字典、ID、实测边长、末端固定方式、拟合/选择/测试姿态数量、剔除规则 | experiment.yaml、pose_log.csv、raw.bag、samples_latest.yaml |
| 外参求解 | 算法及版本、父子 frame、平移 t、旋转矩阵 R、四元数 xyzw、齐次矩阵 T | 候选 extrinsics YAML、opencv.txt |
| 验证精度 | 样本内与留出集分别记录，位置 mm 与旋转 ° 的均值/RMSE/P95/最大值 | 各验证目录 report.json、poses.csv |
| 任务效果 | 独立抓取次数/成功次数、工作区、目标类别、判定标准、偏差和失败原因 | 新的实测记录与视频 |

建议论文分别给出四张表：实验条件、实际使用的内参、外参结果、验证/任务指标。图可包含 ArUco 识别图、采样位姿分布、逐姿态一致性误差、新旧外参对比，以及独立抓取验证结果。所有未执行项写“待测”，不填计划数量或历史结果代替本轮数据。

旧结果是经历史任务验证的基线；本次 20 组恢复结果只是另一候选。此前“0.3895 像素”是彩色内参的样本重投影平均误差；“12.18/13.59 mm”是旧/新外参在同一批 20 组姿态上的位置一致性残差，三者不是同一个评价指标。

论文表格草稿见 [手眼标定论文记录模板](手眼标定论文记录模板.md)。新候选通过验证后，再在日常工作台用 `calibration_file:=新文件绝对路径` 指定它；原基线文件继续保留。
